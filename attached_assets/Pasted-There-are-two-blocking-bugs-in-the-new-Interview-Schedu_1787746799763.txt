# BUG 1 — Interviewer list returns 500

In Admin → Schedule Interview, the Interviewer field shows:

`Failed to load interviewer list`

Browser console shows:

`GET /api/admin/interviewers ... 500 Internal Server Error`

## Required investigation

Do not guess.

1. Reproduce the request directly.
2. Inspect the full server-side error/stack trace for:
   `GET /api/admin/interviewers`
3. Report the exact root cause before changing code.
4. Determine whether the failure comes from:

   * database query
   * Microsoft Graph call
   * missing/expired Graph credentials
   * invalid response parsing
   * missing environment configuration
   * incorrect route implementation
   * some other issue

## Important architecture rule

The interviewer selector itself must NOT become unusable simply because Microsoft Graph availability is unavailable.

Microsoft Graph is an optional availability helper.

If the interviewer list represents OnSpot/Admin users stored in our own system, load those users independently from Microsoft Graph.

Then use Graph only when checking the selected interviewer's Outlook availability.

Desired behavior:

### Interviewer directory works

Admin can select the interviewer.

### Graph available

Show/check Outlook availability.

### Graph unavailable

Display a graceful availability warning such as:

`Outlook availability is currently unavailable.`

But do not crash the interviewer list endpoint.

Do not remove or weaken the existing Graph functionality.

Fix the actual root cause and preserve existing Graph availability behavior.
