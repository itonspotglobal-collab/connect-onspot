# REPLIT TASK: Fix Portal Background, Retire Old Signup Page, and Redesign Login UI

## Objective

Improve the consistency of OnSpot's authentication experience by making three targeted changes:

1. Fix the `/portal` page's background.
2. Remove the outdated `/signup` page from the active signup experience.
3. Redesign the Login portal and login forms to match the existing signup modal design.

Use the three attached screenshots as references.

**Important:** This is a frontend UI/UX and routing cleanup task. Do not modify the existing authentication backend, database, or account registration logic.

---

## 1. Fix the `/portal` Background

### Current Issue

The `/portal` route successfully displays the new "Get started with OnSpot" modal, but the homepage behind it looks visually incorrect.

The background appears to be showing an awkward or improperly positioned section of the homepage.

### Expected Behavior

When a user directly visits `/portal`:

- Render the actual OnSpot homepage behind the signup selection modal.
- Start the homepage at the top, showing the intended hero section.
- Ensure the homepage is correctly positioned and fully rendered.
- Apply a subtle blur and dark overlay to the homepage.
- Keep the signup modal sharp, centered, and clearly visible.

### Implementation Requirements

- Reuse the actual homepage component.
- Do not use a screenshot or static background image.
- Do not duplicate the homepage markup.
- Ensure the homepage is rendered at scroll position 0 when `/portal` is opened directly.
- Prevent inherited scroll positions from causing the homepage to display an unintended section.
- Make sure the background occupies the full viewport without clipping, unexpected white areas, or horizontal overflow.
- Keep the existing homepage header and hero visible behind the overlay.
- Use the same blur and dimming treatment as the existing Talent and Client signup modals.
- Do not apply blur directly to the modal.

For signup modals opened from an existing public page, preserve the user's original page and scroll position instead of forcing the homepage.

### Preserve the Current Portal Modal

Do not change the existing:
- OnSpot logo
- "Get started with OnSpot" heading
- Client and Talent selection cards
- Card sizing and spacing
- Close button
- Dark navy styling
- Signup navigation

Only correct the background rendering and positioning.

## 2. Retire the Outdated `/signup` Page

### Current Issue

The existing `/signup` page still displays the old standalone signup selection design with:

- Light blue gradient background
- Old text-based OnSpot logo
- White selection card
- Outdated visual styling

This page is no longer needed because the new signup popup experience is already available.

### Required Changes

Retire the outdated `/signup` landing page.

Instead of leaving the route broken, implement a redirect:

`/signup` → `/portal`

Requirements:

- Redirect visitors from `/signup` to `/portal`.
- Use a route replacement so the browser Back button does not loop between the two routes.
- Remove the outdated signup page from active navigation.
- Update existing links pointing to `/signup` to use `/portal` or the appropriate direct signup route.
- Remove unused legacy signup landing components and styles only after confirming they are not required elsewhere.
- Do not delete shared registration components.
- Do not remove existing signup APIs or authentication logic.

### Preserve the Dedicated Signup Routes

These routes must remain functional:

`/portal` — Client/Talent signup selection modal

`/signup/talent` — Direct Talent signup modal

`/signup/client` — Direct Client signup modal

These URLs will be used for email campaigns and invitations.

Ensure `/signup` redirects correctly without accidentally intercepting `/signup/talent` or `/signup/client`.

## 4. Maintain Consistent Modal Navigation

The Login and Signup flows should behave consistently.

### Signup

- `/portal` opens the signup selection modal.
- `/signup/talent` opens the Talent signup modal.
- `/signup/client` opens the Client signup modal.
- Clicking X closes the modal and returns users to the appropriate page.
- Back to Portal returns to the signup selection modal.

### Login

- `/login` opens the login selection modal.
- Selecting Client opens the existing Client login form.
- Selecting Talent opens the existing Talent login form.
- Back to Portal returns to the login selection modal.
- Clicking X closes the modal and returns users to the originating page or homepage when directly accessed.

Preserve the existing original-page tracking functionality.

Do not introduce redirect loops.

Keep browser Back and Forward behavior consistent with the current URL and modal state.
