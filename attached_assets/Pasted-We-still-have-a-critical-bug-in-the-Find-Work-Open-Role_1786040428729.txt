We still have a critical bug in the Find Work / Open Roles feature.

Previous pagination changes did NOT fix the underlying issue.

### Current production behavior

When there are more than 25 open jobs:

* Only the newest 25 jobs exist in the Find Work results.
* The displayed count stays at:

```text
25 roles found
```

* Posting a 26th job causes the oldest visible job to disappear.
* Posting 50 or 100 jobs still results in only 25 jobs being discoverable.
* The missing older jobs cannot be found through normal browsing.
* Deleting some newer jobs causes older jobs to appear again.

This proves that somewhere in the request flow, the application is treating the **first 25 records as the complete result set**.

Do NOT make another frontend-only pagination fix.

Do NOT simply change `25` to `50`, `100`, `200`, or another larger value.

Find and fix the actual backend/data-layer issue.

# Correct backend architecture

The required execution order is:

```text
DATABASE
   ↓
all matching open jobs
   ↓
apply search/filter conditions
   ↓
COUNT total matching records
   ↓
apply sorting
   ↓
apply LIMIT 25 / OFFSET
   ↓
return current page + total metadata
```

It must NOT be:

```text
DATABASE
   ↓
take newest 25
   ↓
filter them
   ↓
count them
   ↓
return 25
```

That second flow is the current bug pattern.

# Implement true server-side pagination

For page-based pagination:

```ts
const page = Math.max(1, Number(req.query.page) || 1);
const pageSize = 25;

const offset = (page - 1) * pageSize;
```

The backend needs TWO logical queries.

## Query 1 — total count

Equivalent to:

```sql
SELECT COUNT(*)
FROM jobs
WHERE status = 'open';
```

plus whatever search/filter conditions are active.

This query must NOT contain:

```sql
LIMIT
```

or:

```sql
OFFSET
```

Example:

```ts
const total = Number(countResult.rows[0].count);
```

## Query 2 — page records

Equivalent to:

```sql
SELECT *
FROM jobs
WHERE status = 'open'
ORDER BY created_at DESC
LIMIT 25
OFFSET $offset;
```

Then:

```ts
const totalPages = Math.ceil(total / pageSize);
```

Return:

```ts
res.json({
  items,
  meta: {
    page,
    pageSize,
    total,
    totalPages,
  },
});
```

---

# Very important: stable sorting

Use a deterministic sort.

Prefer:

```sql
ORDER BY created_at DESC, id DESC
```

Do not rely only on an unstable order.

This prevents jobs from unexpectedly moving between pages when records have similar timestamps.
