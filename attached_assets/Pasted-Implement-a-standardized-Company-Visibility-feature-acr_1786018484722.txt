Implement a standardized Company Visibility feature across the entire Find Work / Job Posting system.

GOAL

When creating or editing a job posting, the client/admin should be able to choose whether:

1. The actual company is publicly displayed
OR
2. The company remains confidential

If confidential is selected, candidates should see:

Confidential Company

instead of the actual company name.

The actual company information must still remain stored internally.

IMPORTANT:
Apply this consistently across ALL related pages and components, including:

- Find Work Admin
- Add Job Posting
- Edit Job Posting
- Admin job listing
- Job preview
- FindWork/AllJobs
- regular job cards
- Featured job cards
- Job Details / View Details
- application page
- similar jobs
- any search/filter component displaying company information
- backend/API
- shared job types/interfaces
- database/schema if necessary

--------------------------------------------------
1. COMPANY VISIBILITY FIELD
--------------------------------------------------

First inspect whether the project already has something like:

isCompanyConfidential
hideCompanyName
companyVisibility
isConfidential

If an equivalent field already exists, REUSE IT.

Do not create duplicate fields.

If nothing exists, add:

isCompanyConfidential: boolean

Default:

false

Meaning:

false
→ public company information may be displayed

true
→ company identity must be hidden publicly

--------------------------------------------------
2. COMPANY INFORMATION
--------------------------------------------------

The job should retain actual company information regardless of visibility.

Use existing fields if available.

Ideally:

companyName
companyDescription
isCompanyConfidential

Example:

{
  companyName: "AboitizPower",
  companyDescription:
    "A leading Philippine energy company focused on sustainable power solutions.",
  isCompanyConfidential: false
}

Confidential example:

{
  companyName: "AboitizPower",
  companyDescription:
    "A leading Philippine energy company...",
  isCompanyConfidential: true
}

IMPORTANT:

Do NOT replace the stored companyName with the literal string:

"Confidential"

The actual name must remain available internally.

Confidentiality is only a presentation rule.

4. COMPANY DESCRIPTION
--------------------------------------------------

Add/support a short company description.

Suggested field:

Use a textarea.

If some reasonable database limit already exists, preserve it.

Company description should be OPTIONAL.

--------------------------------------------------
5. ADMIN SHOULD ALWAYS SEE REAL COMPANY
--------------------------------------------------

Confidentiality only applies to candidate/public-facing pages.

Inside Find Work Admin:

Always show the actual company name.

For confidential postings, add a badge:

[Confidential publicly]

Example:

Senior Account Executive
AboitizPower
[Confidential publicly]

This allows admins to identify the client while understanding what candidates see.

--------------------------------------------------
6. PUBLIC DISPLAY HELPER
--------------------------------------------------

Create ONE shared helper rather than repeating confidentiality checks everywhere.

Example:

export function getPublicCompanyName(job: Job) {
  return job.isCompanyConfidential
    ? "Confidential Company"
    : job.companyName;
}

For description:

export function getPublicCompanyDescription(job: Job) {
  if (job.isCompanyConfidential) return null;

  return job.companyDescription?.trim() || null;
}

Use equivalent architecture appropriate to the existing project.

13. API PRIVACY
--------------------------------------------------

IMPORTANT SECURITY REQUIREMENT:

Do not rely only on React hiding the company name.

Inspect the public API.

If possible, public job endpoints should NOT expose confidential company information unnecessarily.

For example, public API mapping may return:

{
  companyName: "Confidential Company",
  companyDescription: null,
  isCompanyConfidential: true
}

instead of returning the real companyName and merely hiding it in React.

Admin-authenticated endpoints should still receive the real information.

This prevents someone from opening DevTools / Network and discovering confidential clients.

16. EXISTING JOBS
--------------------------------------------------

There are already existing postings.

Do NOT automatically convert every job currently containing:

"Confidential"

into a fake company.

Inspect legacy records.

companyName === "Confidential"

and no real company name exists,

preserve it temporarily and flag it for admin review.

If actual company data exists elsewhere, only migrate it when the relationship is explicit and safe.

--------------------------------------------------
17. VALIDATION
--------------------------------------------------

Company Name should still be required internally even when the posting is confidential.

Why:

Admin needs to know which client owns the role.

So:

companyName = required

companyDescription = optional

isCompanyConfidential = boolean

Do NOT allow confidentiality to make companyName optional unless the existing architecture genuinely cannot supply it.

--------------------------------------------------
18. PREVIEW PUBLIC PAGE
--------------------------------------------------

The Admin "Preview public page" feature must respect the confidentiality setting.

If checkbox/toggle is enabled, Preview should show:

Confidential Company

not the real company.

This allows admins to verify exactly what candidates will see.

--------------------------------------------------
19. SEARCH / FILTER SAFETY
--------------------------------------------------

Inspect public search/filter functionality.

A confidential company's real name must not be searchable publicly.

Example:

If AboitizPower has a confidential posting:

Searching "AboitizPower" should NOT reveal that job because the backend still matched a hidden company name.

Public search must use only publicly exposed company values.
