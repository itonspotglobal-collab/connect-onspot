Enhance the existing Admin Job Applications Resume / CV functionality.

GOAL:

For applicants who already have an OnSpot Talent account / Candidate Profile, I want Admin Application Details to also retrieve the resume/CV they originally uploaded during the Find Best Matches setup.

This applies especially when the job application itself does NOT have a resume attached.

==================================================
CURRENT DATA MODEL
==================================================

The codebase already has two possible resume sources:

1. Job-specific application resume:

job_submissions.resume_url
job_submissions.resume_file_name

2. Candidate / Find Best Matches resume:

candidates.resume_url
candidates.resume_file_name

The candidates table is used by the Find Best Matches / Candidate Profile flow.

DO NOT create another resume table or duplicate storage system.

==================================================
RESUME PRIORITY
==================================================

For Admin Application Details use this exact priority:

FIRST:
Resume uploaded with this specific job application.

Use:

job_submissions.resume_url
job_submissions.resume_file_name

SECOND:
If the application has no resume, find the linked Talent/Candidate profile and use:

candidates.resume_url
candidates.resume_file_name

THIRD:
If neither exists:

show:

"No CV available for this applicant."

==================================================
EXISTING TALENT ACCOUNT MAPPING
==================================================

This is the important part.

job_submissions currently contains:

talent_id

That may reference users.id.

Find Best Matches candidate data lives in:

candidates

Inspect the current account-creation/linking flow and determine how:

users
talent account
candidate profile

are connected.

Do NOT guess candidate IDs on the frontend.

Resolve the candidate server-side.

Preferred mapping order:

1. If there is already an explicit user/candidate relationship in the database, use it.

2. If the current architecture links Candidate accounts by normalized email, use:

LOWER(TRIM(candidates.email))
=
LOWER(TRIM(users.email))

or application email where appropriate.

3. Prefer an explicit persistent relationship over email matching if one exists.

Do not rely only on names.

==================================================
IMPORTANT EMAIL FALLBACK
==================================================

For existing Talent accounts that came through Find Best Matches, the candidate record may have the same email as:

job_submissions.email

Therefore, if there is no explicit candidate ID relationship yet, temporarily resolve candidate using normalized email:

SELECT ...
FROM candidates
WHERE LOWER(TRIM(email)) = LOWER(TRIM($applicationEmail))
LIMIT 1

But inspect the existing architecture first.

If multiple Candidate records can exist for one email, choose the correct/current profile deterministically, preferably:

profileCompleted = true
and/or
most recently updated

Do not silently choose an arbitrary record.

==================================================
ADMIN APPLICATION DETAIL API
==================================================

Update:

GET /api/admin/job-applications/:id

The response should resolve the resume before returning it.

Return normalized fields:

{
  ...
  resumeUrl,
  resumeFileName,
  resumeSource,
  candidateId
}

Where:

resumeSource = "application"
when using job_submissions resume

resumeSource = "talent_profile"
when using Find Best Matches Candidate resume

resumeSource = null
when no resume exists

Example:

{
  "id": "...",
  "talentId": "...",
  "candidateId": "...",
  "resumeUrl": "/api/admin/job-applications/.../resume",
  "resumeFileName": "Val_Legaspi_Resume.pdf",
  "resumeSource": "talent_profile"
}

Do NOT send a private object-storage path directly to the browser.

==================================================
RESUME SERVING ENDPOINT
==================================================

Update the existing endpoint:

GET /api/admin/job-applications/:id/resume

so that it resolves resume source using the same priority:

const applicationResume = submission.resumeUrl;

if (applicationResume) {
   serve application resume;
} else {
   resolve linked candidate;
   if (candidate.resumeUrl) {
      serve candidate resume;
   }
}

The endpoint should return the actual file.

Preserve:

Content-Type

and:

Content-Disposition

using the resolved filename.
