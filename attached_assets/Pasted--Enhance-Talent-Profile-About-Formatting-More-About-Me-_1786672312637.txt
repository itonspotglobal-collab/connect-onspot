# FEATURE 1 — Improve About Section Formatting

## Current issue

The current About section can contain a large amount of text, but it renders visually like one dense block of text.

This makes the section feel crowded and difficult to read.

We want the About section to display as proper **paragraph-form content**.

---

## Desired behavior

Keep the existing About field and data source.

Do NOT create another About field.

Improve only how it is entered and rendered.

When the Talent writes multiple paragraphs such as:

```text
I am an entrepreneur, executive, and company builder focused on turning ambitious ideas into scalable businesses.

My career has been built at the intersection of strategy, technology, operations, and people.

Today, much of my focus is on technology-enabled businesses and new operating models.
```

the profile should render them visually as separate paragraphs with natural spacing.

Do not collapse everything into one continuous wall of text.

---

# About Rendering

Preserve line breaks and paragraph breaks entered by the Talent.

Preferred output behavior:

```tsx
<p>First paragraph...</p>

<p>Second paragraph...</p>

<p>Third paragraph...</p>
```

or an equivalent implementation such as:

```tsx
whitespace-pre-line
```

if it produces the correct readable result.

However, proper paragraph spacing is preferred.

Example:

```tsx
value
  .split(/\n\s*\n/)
  .filter(Boolean)
  .map(...)
```

Do not use `dangerouslySetInnerHTML`.

Do not interpret user-entered text as HTML.

---

# About Styling

The About section should have:

* comfortable line height
* readable paragraph width
* clear spacing between paragraphs
* consistent text size
* no excessive indentation
* no justified text
* no strange word wrapping

Suggested styling:

```text
text-sm / text-base
leading-7
text-slate-700
space-y-4
```

Adapt this to the existing Talent Profile design.

The screenshot supplied with this request demonstrates the current dense block that needs improvement.

# About Editing

The owner must still be able to edit the About section.

The textarea should support multiple paragraphs naturally.

When editing:

* Enter = new line
* blank line = new paragraph
* saving must preserve paragraph breaks

Do not strip newline characters from the saved value.

If the current backend or update function trims the value, trimming leading/trailing whitespace is fine, but preserve internal newlines.

# FEATURE 3 — Talent Public View

Add a feature allowing the Talent to preview their profile exactly from a visitor's perspective.

The Talent currently has an owner view where editable controls appear.

We need a clear way to switch into:

**Public View**

This is not a separate editable version of the profile.

It is a read-only preview of the existing profile.

---

# Public View Meaning

Public View represents:

> “What does another person see when they visit my Talent Profile?”

When Public View is enabled:

* no Pencil icons
* no Add buttons
* no Delete buttons
* no upload controls
* no editable textareas
* no edit modals
* no profile photo upload overlay
* no owner-only management UI
* no private application information
* no owner-only account controls inside the profile body

All profile information should be read-only.

---

# Important: Reuse the Same Profile UI

Do NOT build:

```text
TalentProfile.tsx
PublicTalentProfile.tsx
```

as two completely duplicated implementations.

Use the same Talent Profile rendering and derive:

```ts
canEdit
```

from something like:

```ts
isOwner && !isPublicPreview
```

Conceptually:

```ts
const canEdit = isOwner && !publicView;
```

Then pass `canEdit` through existing editable components.

This prevents the owner profile and public profile from visually drifting apart.

---

# Public View Entry Point

Add a clearly visible button for the profile owner.

Recommended location:

Near the Talent profile header actions.

Button:

```text
[Eye icon] Public View
```

or:

```text
Preview Public Profile
```

Use the existing Lucide `Eye` icon if already imported.

Do not put the button in every section.

It should be a single profile-level action.

---

# Preferred Public View UX

When Talent clicks:

**Public View**

switch the existing page into public-preview mode.

Recommended URL strategy:

```text
/talent-profile/:candidateId?view=public
```

or:

```text
/talent-profile/:candidateId?preview=public
```

Use whichever fits the current router cleanly.

Using a URL state is preferable because:

* refresh preserves preview
* browser Back works
* link state is understandable
* UI state does not get lost

Do not create fragile localStorage-based preview state.

# Final Implementation Rules

Do not create two independent Talent Profile implementations.

The target architecture should remain:

```text
Talent Profile data
        ↓
same TalentProfile UI
        ↓
┌──────────────────────────────┐
│ Owner Edit View              │
│ isOwner = true               │
│ publicPreview = false        │
│ canEdit = true               │
└──────────────────────────────┘

┌──────────────────────────────┐
│ Owner Public Preview         │
│ isOwner = true               │
│ publicPreview = true         │
│ canEdit = false              │
└──────────────────────────────┘

┌──────────────────────────────┐
│ Actual Visitor               │
│ isOwner = false              │
│ canEdit = false              │
└──────────────────────────────┘
```

The Public View must be a faithful preview of the actual visitor profile.

Keep profile data, rendering, and visibility logic centralized.

Do not create duplicate data sources or duplicate profile components.
