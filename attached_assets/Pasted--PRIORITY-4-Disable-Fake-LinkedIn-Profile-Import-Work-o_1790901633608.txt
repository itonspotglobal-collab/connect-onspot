## PRIORITY 4 — Disable Fake LinkedIn Profile Import

Work on **Priority 4 only**.

Do not proceed to Priority 5.

This is a **small MVP safety/correctness fix**, not a LinkedIn integration project.

---

# Problem

The application currently contains a LinkedIn profile import/connect flow that appears to simulate a real LinkedIn integration.

The existing implementation can write fabricated/sample LinkedIn information into a real Talent profile.

Previous source inspection identified behavior equivalent to:

- simulated LinkedIn OAuth/connect
- fake/sample LinkedIn profile data
- `"Sample User"` or equivalent placeholder identity
- fabricated skills/profile information
- persistence of that simulated information into the Talent profile

This is unacceptable for the MVP because a user can reasonably believe their real LinkedIn profile was imported when the application actually stores fabricated data.

The immediate Priority 4 objective is:

> **Disable/hide the fake LinkedIn profile import functionality completely until a real provider-backed profile import integration exists.**

Do NOT build real LinkedIn OAuth/profile import as part of this priority.

---

# IMPORTANT DISTINCTION — DO NOT BREAK LINKEDIN SIGN-IN

Before changing anything, determine whether the project has two separate concepts:

### A. LinkedIn authentication/sign-in

For example:

`Sign in with LinkedIn`

through Passport or another provider-backed authentication flow.

### B. LinkedIn profile connect/import

For example:

`Connect LinkedIn`

or:

`Import from LinkedIn`

inside Talent onboarding/profile/Get Hired.

Priority 4 applies to **B only**.

If provider-backed LinkedIn authentication exists separately and is legitimate, DO NOT disable or modify it.

Do not confuse:

`LinkedIn login`

with:

`LinkedIn profile import`

# PHASE 3 — IMPLEMENT THE MVP STOPGAP

The approved MVP behavior is:

## Remove/hide the LinkedIn profile import action

Users must no longer be presented with a button/action suggesting that the application can import their LinkedIn profile.

Examples include:

- `Connect LinkedIn`
- `Import from LinkedIn`
- `Sync LinkedIn`
- similar profile-import actions

Remove/hide the functionality from all Talent-facing UI locations where it invokes the fake import.

Do not replace it with another fake integration.

Do not display:

`Coming Soon`

unless the existing product design consistently uses that pattern and it adds value.

For the cleanest MVP, simply remove the unavailable action while preserving legitimate manual profile editing.

---

# PHASE 4 — DISABLE THE DANGEROUS BACKEND PATH

Do not rely only on hiding the frontend button.

The fake persistence endpoint must also no longer be capable of writing fabricated profile information.

If:

`POST /api/linkedin/connect`

or an equivalent route is specifically the simulated profile-import endpoint, disable/remove that behavior.

Preferred options, depending on the existing architecture:

### Option A — Remove the route

If nothing legitimate depends on it, remove the fake endpoint entirely.

### Option B — Explicitly return unavailable

If removing it could break compatibility or existing clients, make it return an appropriate non-success response indicating that LinkedIn profile import is unavailable.

For example:

`404`, `410`, or another appropriate application-consistent response.

Do NOT return:

`200 success`

with fake data.

Do NOT persist:

- `"Sample User"`
- fabricated skills
- fake headline
- fake profile picture
- fake employment data
- any other simulated LinkedIn information

Choose the smallest approach consistent with the project's routing conventions.
