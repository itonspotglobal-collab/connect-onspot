# AUTO-FILL TALENT PROFILE FROM RESUME UPLOADED ANYWHERE

You are working inside the existing **OnSpot / connect-onspot** project.

We have already been consolidating resume handling so the Candidate has one canonical resume.

Now implement the next phase:

## Whenever a Talent uploads or replaces a resume from ANY supported Talent flow, automatically parse that resume and use it to populate the Talent's Candidate Profile.

Resume uploads can currently happen from areas such as:

1. Create Talent Account / Signup
2. Find Best Matches onboarding
3. Talent Profile
4. Talent Profile Settings
5. Get Hired / onboarding if still active

All of these must use the SAME parsing + profile update pipeline.

Do NOT implement separate resume parsing logic for each page.

---

# Main Goal

The desired architecture is:

```text
Upload Resume Anywhere
        ↓
Save canonical Candidate resume
        ↓
Parse Resume
        ↓
Extract structured professional information
        ↓
Merge into SAME Candidate record
        ↓
Invalidate/update Candidate caches
        ↓
Talent Profile prefilled
        ↓
Talent Profile Settings prefilled
        ↓
Find Best Matches uses same profile
```

The resume should not only be attached.

It should automatically populate the candidate's actual professional profile.

---

# IMPORTANT PRODUCT BEHAVIOR

When a resume contains information such as:

```text
Phone: +63...
Location: Cebu City, Philippines
Title: Full Stack Developer
Summary: ...
Skills: React, TypeScript, Node.js
Experience: Software Developer — Company A
Education: BS Computer Engineering — University X
Certification: AWS Certified...
Languages: English, Filipino
```

the Candidate should automatically receive those values.

Then:

**Talent Profile** should show them.

**Talent Profile Settings** should show them.

The user should only need to:

> Review and correct the imported information.

They should not have to manually type information already present in their CV.

# 5. IMPORTANT MERGE RULE — DO NOT DESTROY EXISTING PROFILE DATA

A resume replacement must NOT blindly erase high-quality existing profile data.

Implement a safe merge strategy.

## Empty Candidate field

If Candidate field is empty:

```text
Candidate phone = empty
Resume phone = +63...
```

then:

```text
candidate.phone = resume phone
```

---

## Candidate already has data, resume also has data

For onboarding/new account flow, parsed resume data can populate the field automatically.

For an EXISTING Candidate replacing their resume, be careful.

Do NOT automatically wipe manually curated profile content with empty parser results.

At minimum:

```ts
parsed non-empty && existing empty
    → use parsed

parsed empty
    → preserve existing
```

For existing non-empty fields, choose a consistent product behavior.

Recommended:

### Contact/title/basic structured fields

A newly uploaded resume can update fields such as:

```text
phone
location
targetPosition
skills
experience
education
certifications
```

if the parser has a confident non-empty value.

### Rich user-edited fields

For:

```text
summary / About / Professional Bio
```

do not replace a meaningful existing manual profile with a low-confidence extraction.

Prefer existing manually edited content unless:

* existing field is empty, or
* parser confidence is high and product intentionally wants resume replacement to refresh it.

Document the chosen behavior.

---

# 6. NEVER REPLACE DATA WITH EMPTY VALUES

This is mandatory.

Bad:

```ts
candidate.phone = extracted.phone;
```

if:

```ts
extracted.phone === ""
```

because it would delete an existing phone number.

Use merge behavior like:

```ts
phone:
  extracted.phone?.trim()
    ? extracted.phone.trim()
    : candidate.phone
```

Apply the same principle everywhere.
