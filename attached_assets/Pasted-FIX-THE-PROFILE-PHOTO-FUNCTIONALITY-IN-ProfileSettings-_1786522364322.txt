# PART 2 — REUSE THE WORKING IMPLEMENTATION

The Settings page currently has its own implementation similar to:

```tsx

formData.append("photo", file);

```

This currently returns 401.

REPLACE this flow with the SAME implementation used by the working Talent Profile page.

Do not maintain two different photo-upload implementations.

Prefer extracting the working logic into a shared hook/helper such as:

```tsx

```

```tsx

```

* Talent Profile
* Profile Settings

# PART 3 — INVESTIGATE THE 401

Before changing random authentication code, inspect why this specific request returns 401.

Check:

* Does `authAPI.post()` automatically attach the authorization token?
* Does it correctly handle `FormData`?
* Is it forcing `Content-Type: application/json`?
* Is the multipart boundary being lost?
* Does the working Talent Profile implementation use another API client?
* Does the route require cookie authentication?
* Is `credentials: "include"` missing?
* Is `/api/profiles/me/photo` even the same protected endpoint used by Talent Profile?
* Is the server expecting another form field name?
* Does the existing photo route use the authenticated `user.id` differently?

DO NOT bypass authentication.

DO NOT make the photo endpoint public.

Fix the client request to use the same secure authenticated method that is already proven to work.
