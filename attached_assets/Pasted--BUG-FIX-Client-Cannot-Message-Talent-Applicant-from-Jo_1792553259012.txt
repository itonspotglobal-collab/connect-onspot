# BUG FIX: Client Cannot Message Talent Applicant from Job Submissions

## Problem Description

A new bug has been reported in the Client account's Job Submissions section.

When a Client views applicants who submitted applications for their job posting and clicks the **Message** button beside an applicant, the application fails to open or create a conversation.

**Actual error:**
"Unable to open conversation. Please try again."

## Steps to Reproduce

1. Log in using a Client account.
2. Navigate to the Client Dashboard.
3. Open the Job Submissions section.
4. Locate an applicant who applied for a job.
5. Click the "Message" button beside the applicant.
6. Observe that an error toast appears instead of opening the conversation.

**Example scenario:**
- Applicant: Ica Jael Atendido
- Position: Executive Assistant
- Application date: October 20, 2026
- Application status: NEW

These details are only for identifying the reported scenario. Do not hardcode any user, applicant, or job identifiers.

## Expected Behavior

When the Client clicks "Message":

1. The system identifies the correct Talent account associated with the job application.
2. It verifies that the Client is authorized to contact that applicant.
3. If an existing conversation exists between the Client and Talent in the appropriate job context, open it.
4. If no conversation exists, securely create a new conversation.
5. Navigate to the messaging interface or open the existing conversation panel.
6. Allow the Client to send messages to the Talent.
7. Allow the Talent to receive and reply to those messages.
8. Ensure the conversation persists after refreshing or logging in again.

## TASK 1: Investigate the root cause

Trace the entire messaging flow from:

Client Job Submissions → Message button → Messaging API → Conversation creation/retrieval → Database → Messages UI.

Inspect the actual codebase and identify:

- The frontend component rendering Job Submissions.
- The Message button's click handler.
- The API endpoint called when the Client clicks Message.
- The request payload being sent.
- The authentication middleware.
- The conversation creation and retrieval logic.
- The database tables involved.
- The navigation logic after conversation creation.

Check browser network errors and backend logs to identify the exact failing request, HTTP status code, and server-side error.

Do not assume the cause without confirming it.

## TASK 2: Verify Client and Talent account mapping

Investigate whether the application correctly maps:

- Client user ID
- Client profile ID
- Job ID
- Job application ID
- Candidate/Talent profile ID
- Talent user ID
- Messaging conversation participants

Pay particular attention to whether the messaging system expects `users.id` while the Job Submissions feature supplies `candidates.id` or another identifier.

Ensure the correct user identifiers are used.

Do not modify unrelated user IDs or existing database relationships.

## TASK 3: Fix conversation creation and retrieval

Ensure clicking Message correctly creates or retrieves the appropriate conversation.

Requirements:

- If a valid conversation already exists, reuse it.
- If no conversation exists, create one using the correct participants and job context.
- Prevent accidental duplicate conversations caused by repeated clicks or concurrent requests.
- Ensure the authenticated Client is associated with the relevant job posting or has the appropriate authorization.
- Ensure the Talent is associated with the submitted application.
- Preserve existing conversations and message history.
- Do not create conversations with invalid or missing participant IDs.

Handle errors properly and return meaningful API responses.

## TASK 4: Verify messaging permissions

Review existing messaging authorization and business rules.

Confirm that:

- A Client can message an applicant for their own job posting when allowed by the application's messaging policy.
- A Talent can reply to an authorized Client conversation.
- Clients cannot access unrelated applicants' private conversations.
- Talent users cannot access conversations belonging to other Talent accounts.
- Authentication and authorization remain enforced.

Do not bypass or disable existing messaging security to fix this issue.

If an existing business rule intentionally restricts messaging at a particular application stage, preserve that rule and report the restriction instead of silently changing it.

## TASK 5: Fix frontend messaging behavior

Update the relevant Job Submissions component.

When clicking Message:

- Show an appropriate loading state.
- Prevent duplicate requests while loading.
- Retrieve or create the conversation.
- Open the correct conversation after success.
- Display a clear error message if the operation fails.
- Avoid navigating to an invalid or empty conversation.
- Preserve the existing UI design.

Do not redesign Job Submissions or the messaging interface.

## TASK 6: Verify Messages functionality

Test the complete messaging experience.

Confirm that:

1. Client clicks Message from Job Submissions.
2. The correct Talent conversation opens.
3. Client sends a message.
4. Talent receives the message.
5. Talent replies.
6. Client receives the reply.
7. Both users can view conversation history.

9. Existing conversations continue working.

Ensure the conversation appears correctly in the Messages section for both authorized users.
