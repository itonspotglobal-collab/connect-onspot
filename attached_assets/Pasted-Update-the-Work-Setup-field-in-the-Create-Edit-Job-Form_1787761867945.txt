Update the **Work Setup** field in the Create/Edit Job Form.

This is a small, focused change. Do not modify unrelated JobFormPage functionality.

## Required UI change

Currently the form displays:

**Work Setup — optional**

with a single `Remote` pill/button.

Replace this with:

**Work Setup**

Remove the `— optional` text completely.

Change the existing Remote pill/button into a dropdown/select.

The dropdown must contain exactly these three user-facing choices:

* Remote
* Onsite
* Hybrid

Use the same existing Select/dropdown component and styling already used elsewhere in the Job Form so it visually matches fields such as:

* Function
* Experience Level
* Engagement Type
* Duration

Do not create a custom dropdown if the project already has a shared Select component.

## Important — inspect the existing data mapping first

Before changing the implementation, determine exactly what field currently stores the existing `Remote` Work Setup value.

Trace:

Work Setup UI
→ JobFormData
→ create/edit job payload
→ server route
→ jobs database column
→ job display/search/filtering

Do not introduce a new database field unless genuinely necessary.

If the existing field can safely store:

* Remote
* Onsite
* Hybrid

continue using that field.

## Required behavior

### Create Job

The Client/Admin can select:

`Remote`
`Onsite`
`Hybrid`

The selected value must remain when moving between:

Basics
→ Description
→ Requirements
→ Review

### Edit Job

When editing an existing job:

* Remote → show `Remote`
* Onsite → show `Onsite`
* Hybrid → show `Hybrid`

Do not reset the value when opening Edit Job.

### Review

The Review step should display the selected Work Setup correctly.

### Saved job

After creating/updating and refreshing the page, the selected value must still be correct.

## Existing Remote jobs

Backward compatibility is required.

Existing jobs currently stored as Remote must continue loading as:

`Remote`

Do not migrate or rewrite existing Remote jobs unnecessarily.

## Required vs optional

Remove the visible:

`— optional`

from the Work Setup label.

Before changing validation, inspect whether Work Setup is currently genuinely optional at the data/API level.

For this requested change, make the UI require the user to choose one of:

* Remote
* Onsite
* Hybrid

If the current form already defaults safely to `Remote`, preserving that default is acceptable.

Do not introduce a breaking database constraint merely to make the field required.

Keep backend compatibility with existing records.

## Do not confuse Work Setup with physical location

`Onsite` and `Hybrid` describe the work arrangement.

Do not automatically invent a city/address.

Do not change unrelated location fields or company address data.

If the existing database currently uses a generic `location` field for `Remote`, audit that usage carefully before changing anything.

Do not create fake values such as:

`Onsite - Unknown`

or

`Hybrid - Unknown`
