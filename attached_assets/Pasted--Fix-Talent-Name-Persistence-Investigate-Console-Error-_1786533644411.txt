# Fix Talent Name Persistence + Investigate Console Error Spam

The Talent Profile Settings save is working now, but two problems remain.

Do not rewrite the working Candidate authentication, photo upload, or Settings PATCH architecture.

## Problem 1 — Multi-word First Name is still being moved into Last Name

Current intended values:

```text
First Name: Frenzy Val Eloise
Last Name: Legaspi
```

After Save Settings, the PATCH payload correctly shows:

```text
fullName: "Frenzy Val Eloise Legaspi"
```

But after the page reloads, the form becomes:

```text
First Name: Frenzy
Last Name: Val Eloise Legaspi
```

This is wrong.

The application is still splitting `fullName` somewhere.

## Important requirement

Once a user explicitly enters First Name and Last Name, preserve those two values exactly.

For this example, the database should contain:

```text
first_name = "Frenzy Val Eloise"
last_name  = "Legaspi"
full_name  = "Frenzy Val Eloise Legaspi"
```

Do not reconstruct First Name and Last Name from `fullName` after save.

# 3. Correct Settings load behavior

When loading Profile Settings, do this:

```ts
firstName: candidate.firstName ?? ""
lastName: candidate.lastName ?? ""
```

Do NOT do this for candidates that already have separate values:

```ts
const pieces = candidate.fullName.split(" ");
firstName = pieces[0];
lastName = pieces.slice(1).join(" ");
```

That logic is the bug.

# 4. Legacy fallback only

Older Candidate rows may only have `fullName`.

Only for rows where BOTH separate values are missing, use a one-time fallback:

```ts
function legacyNameFallback(fullName: string) {
  const parts = fullName.trim().split(/\s+/);

  if (parts.length === 0) {
    return { firstName: "", lastName: "" };
  }

  if (parts.length === 1) {
    return {
      firstName: parts[0],
      lastName: "",
    };
  }

  return {
    firstName: parts.slice(0, -1).join(" "),
    lastName: parts.at(-1) ?? "",
  };
}
```

For:

```text
Frenzy Val Eloise Legaspi
```

this gives:

```text
First Name: Frenzy Val Eloise
Last Name: Legaspi
```

This is still only a fallback.

Once the user clicks Save Settings, persist the explicit separate fields and never run the fallback again for that candidate.
