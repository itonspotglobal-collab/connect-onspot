Fix the Client Profile dropdown badge logic in the existing OnSpot / `connect-onspot` application.

## CURRENT ISSUE

The Client dropdown currently shows something like:

```text
Client Profile

Hire Talent   3

Messages      3

Settings
```

The `3` on `Messages` is correct if the Client has 3 unread messages.

But the `3` on `Hire Talent` must NOT come from unread messages.

The Client dropdown is currently mixing message unread count with hiring/application activity.

Fix this separation.

---

# REQUIRED BEHAVIOR

## Messages

The `Messages` dropdown item should show:

the number of unread chat messages.

Example:

```text
Messages   3
```

This should be driven only by the canonical unread-message source.

---

## Hire Talent

The `Hire Talent` dropdown item must NOT react to incoming chat messages.

A Client receiving:

* 1 message
* 3 messages
* 10 messages

must NOT cause any badge on:

`Hire Talent`

---

# WHAT HIRE TALENT BADGE SHOULD REPRESENT

`Hire Talent` is related to:

* Client-posted jobs
* Talent applications/submissions
* hiring pipeline activity

If a badge is shown there, it should represent only relevant hiring/application activity.

Examples:

* new Talent application received
* new/unreviewed job submission
* possibly other explicitly defined hiring actions

Do NOT use:

* unread message count
* message notifications
* `new_message`
* thread unread count

for Hire Talent.

---
