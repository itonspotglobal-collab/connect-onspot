Update the Jobs / Roles sorting behavior so important job postings, especially **Urgently Hiring** roles, do not get pushed down or disappear from the first page simply because newer normal roles are added.

## Current problem

The jobs list is currently heavily based on recency.

When new roles are posted:

```text
new normal roles
↓
older roles move downward
↓
older urgent roles can be pushed to another page
```

This causes roles marked:

```text
URGENTLY HIRING
```

to lose visibility even though they are still actively urgent.

We want urgent roles to remain prioritized near the top until their urgent status is removed, the job is closed, or another existing business rule makes them ineligible.

Do NOT delete, duplicate, or artificially refresh their posted date.

Change the sorting logic instead.

---

# Required sorting priority

For the default job listing, use this priority:

```text
1. Urgently Hiring jobs
2. Featured jobs
3. Regular jobs
```

Within each group, sort by newest posting date first.

Conceptually:

```text
URGENT + newest
URGENT + older
URGENT + oldest

FEATURED + newest
FEATURED + older

REGULAR + newest
REGULAR + older
REGULAR + oldest
```

A new regular job must NOT automatically appear above an older urgent job.

Example:

Existing job:

```text
Delivery Manager
Urgently Hiring
Posted 8 days ago
```

New job:

```text
Virtual Assistant
Not urgent
Posted today
```

Expected:

```text
1. Delivery Manager — URGENTLY HIRING
2. Virtual Assistant — posted today
```

NOT:

```text
1. Virtual Assistant
2. Delivery Manager
```

```text

```

it should still be in the highest-priority urgent group.

Recommended precedence:

```text

```

If desired, implement explicit scoring:

```ts
function getJobPriorityScore(job: Job) {
  let score = 0;

  if (isFeaturedJob(job)) score += 1;
  if (isUrgentJob(job)) score += 2;

  return score;
}
```

This would produce:

```text
Urgent + Featured = 3
Urgent            = 2
Featured          = 1
Regular           = 0
```

Then sort descending by score.

# Very important: apply sorting BEFORE pagination

The correct backend flow must be:

```text
all matching open jobs
↓
filters/search
↓
priority sorting
↓
calculate total
↓
paginate 25 per page
```

Do NOT do:

```text
take 25 newest jobs
↓
then move urgent jobs within those 25
```

because an older urgent role outside those first 25 would still be lost from Page 1.

Example:

There are:

```text
100 open jobs
```

and one urgent job is currently the 40th newest.

The system must first recognize it as urgent and move it near the top BEFORE selecting Page 1.

Expected:

```text
Urgent job appears on Page 1
```

not:

```text
Urgent job remains hidden on Page 2
because pagination happened before sorting
```

This is critical.

# Prefer server-side sorting

Because the Jobs page now supports potentially:

```text
100
1,000
10,000+
```

roles, do NOT fetch every job into the frontend merely to prioritize urgent roles.

Implement priority ordering in:

```text
GET /api/jobs/search
```

where practical.

The server query should behave conceptually like:

```sql
SELECT *
FROM jobs
WHERE status = 'open'
ORDER BY
  urgent_flag DESC,
  featured_flag DESC,
  posted_at DESC,
  id DESC
LIMIT 25
OFFSET ...;
```

Use the project's actual column names.

If urgency is calculated rather than stored as a simple column, reproduce the existing business rule safely in the query/service layer or provide a consistent sortable field.

An urgent role should remain prioritized only while it is eligible to appear.


Priority sorting must happen AFTER visibility filters such as:


have been applied.
