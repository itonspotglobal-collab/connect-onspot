# 2. Add Location Normalization

Create or reuse a normalization helper.

Example:

```ts
function normalizeLocation(value?: string | null): string {
  const normalized = (value ?? "")
    .trim()
    .toLowerCase()
    .replace(/[^a-z0-9]+/g, " ")
    .replace(/\s+/g, " ")
    .trim();

  if (
    normalized === "on site" ||
    normalized === "onsite"
  ) {
    return "onsite";
  }

  if (
    normalized === "remote work" ||
    normalized === "fully remote"
  ) {
    return "remote";
  }

  return normalized;
}
```

Do not modify the stored database value just for filtering.

Normalize only for comparison.

# 9. Salary Filter Needs Special Attention

The Minimum Salary filter is currently handled differently.

In the existing page, salary filtering may still be performed client-side after `/api/jobs/search` returns a page of results.

That is a potential pagination bug.

Current flow may be:

```text
server returns page of 25 jobs
↓
frontend filters those 25 by salary
```

This can incorrectly produce zero results even when salary-matching jobs exist on another page.

Preferred architecture:

```text
all public jobs
↓
category
↓
location
↓
contract
↓
minimum salary
↓
count
↓
pagination
```

Move Minimum Salary filtering server-side if practical.
