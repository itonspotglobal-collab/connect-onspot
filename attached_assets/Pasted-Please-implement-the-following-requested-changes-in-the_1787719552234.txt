# 8. Calendar/interview scheduling recommendation and implementation direction

The screenshot requests:

> Provide suggestions on what calendar (e.g. Google Meet, Teams), we can use to schedule interviews, otherwise we'll have to build our own.

Do NOT build a new calendar platform in this task unless an existing scheduling implementation is broken and only requires a small fix.

First inspect the repository's current interview/invitation scheduling behavior.

The existing invitation flow already supports:

```ts
proposedTimes
```

including timezone information when sending an invitation.

Preserve that.

## Recommendation

Use **Google Calendar + Google Meet** as the preferred first integration.

Reasons:

* simple browser-based experience
* automatic Meet link generation when Calendar API event conferencing is enabled
* broad compatibility for clients and talent
* avoids building a custom video-meeting system
* timezone handling is mature

Microsoft Teams should be a later optional integration for Clients whose organizations use Microsoft 365.

Recommended phased approach:

```text
Phase 1
- Keep existing internal proposed-times flow
- Add Google Calendar integration
- On confirmed interview, optionally create Calendar event
- Generate Google Meet link
- Save external event ID + meeting URL

Phase 2
- Add Microsoft Outlook/Teams via Microsoft Graph
```

Do not replace the existing interview workflow with raw Google Calendar records.

The internal system must remain the source of truth for:

* invitation ownership
* applicant/talent
* client
* job
* interview status
* proposed/confirmed time
* timezone

External calendars should synchronize the confirmed interview.

## If implementing Google Calendar now

Only proceed if the necessary OAuth/integration infrastructure already exists or can be added cleanly.

Store:

* provider
* external event ID
* meeting URL
* calendar sync status

Never store Google credentials in frontend code.

If there is no existing Google OAuth connector, document the required environment variables/scopes instead of hardcoding credentials.
