Audit and implement the following Client-side UX improvements in the existing OnSpot / `connect-onspot` application.

These changes are based on user feedback and must be applied carefully without breaking the existing hiring pipeline.

## THREE REQUIRED CHANGES

1. After a Client logs in, take them to the Talent/Hire Talent page instead of the Client dashboard.
2. When a Client clicks Hire Talent, clearly give them an option to Post a Job.
3. On the Hire Talent search results, replace the main `Shortlist` action with:

   * `Favorite` / Star
   * `Interview` / `Request Interview`

Do NOT destroy the existing shortlist backend/pipeline because other features already depend on it.

# =====================================================


# IMPORTANT — DO NOT DELETE SHORTLIST BACKEND

The repo already has a formal shortlist workflow.

Keep:

* shortlist tables
* shortlist APIs
* shortlist pipeline guards
* existing shortlist status history
* existing Admin/Client workflows that depend on shortlist

We are changing the user-facing action on Hire Talent.

Do not globally rename the database status `shortlisted` to `favorite`.

A Favorite is a lightweight saved Talent action.

Shortlisted remains a formal hiring/application state.

These are different concepts.

# =====================================================

# DISTINGUISH FAVORITE VS SHORTLIST

# =====================================================

This distinction is mandatory.

## Favorite

Private Client bookmark.

No hiring status change.

No Talent notification.

## Shortlisted

Formal application pipeline status.

Requires an actual application/submission.

May trigger notifications/status history according to existing system.

Do NOT merge these concepts.
