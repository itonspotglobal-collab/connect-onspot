## Task: Improve Login and Sign Up Back Navigation and Back Button UI

I want to improve the navigation behavior and back button design across the OnSpot Login and Sign Up pages.

Please use the attached screenshots and updated UI mockup as references.

### 1. Fix "Back to Home" Navigation

**Current behavior:**

When a user visits a page such as "Find Work" and clicks Login or Sign Up, they are redirected to the authentication portal.

If they decide not to continue and click "Back to Home", they are always redirected to the homepage.

**Expected behavior:**

Replace this with intelligent back navigation that returns users to the original page they visited before entering the Login or Sign Up flow.

Example scenario:

1. User is browsing the "Find Work" page.
2. User clicks Login.
3. User is redirected to the Login Portal.
4. User selects "Talent".
5. User decides not to continue.
6. User clicks the back navigation to return to the portal.
7. User clicks "Back to Find Work" or the appropriate return link.
8. User is redirected to the original "Find Work" page instead of the homepage.

Apply the same behavior to Sign Up.

### 2. Preserve the Previous Page Across Authentication Steps

Implement a reliable way to track the user's original page before entering authentication.

Requirements:

- Capture the originating page when the user clicks Login or Sign Up.
- Preserve the original destination while navigating between the Client and Talent portals, login forms, and signup forms.
- Preserve the return destination when switching between Login and Sign Up.
- Do not overwrite the original destination with intermediate authentication pages.
- Use React Router navigation state, session storage, or another appropriate solution compatible with the existing application.
- Do not rely exclusively on `navigate(-1)` or `window.history.back()`, because these may return users to an intermediate authentication page instead of their original destination.
- Validate return destinations so users cannot be redirected to untrusted external websites.
- If the user directly visits the Login or Sign Up page without a valid originating page, fall back to the homepage.

This behavior must work for both Client and Talent authentication flows.

### 3. Clarify the Two Back Navigation Actions

There should be a clear distinction between:

**A. Back to Portal**

Used inside the Client or Talent Login/Sign Up form.

- Returns the user to the Client/Talent portal selection screen.
- Preserves the original page the user came from.
- Does not immediately redirect the user to the homepage.

**B. Back to Previous Page**

Used on the Client/Talent portal selection screen.

- Returns the user to the original page they visited before entering authentication.
- For example, if the user came from "Find Work", return them to "Find Work".
- If they came from another public page, return them to that page.
- If no valid originating page exists, return them to the homepage.

For clarity, use a dynamic label such as "Back to Find Work" when the originating page is known, or "Back to Home" for the fallback.

### 4. Improve the Back Button Design

The current back arrow in the Talent Sign Up form is too small and difficult to notice.

Update it based on the attached UI mockup.

**New button design:**

- Add a left-arrow icon followed by the text **"Back to Portal"**.
- Position it at the top-left of the authentication card.
- Use a rounded rectangular button with a subtle outline.
- Use a light-colored arrow and text for contrast against the dark navy background.
- Add comfortable horizontal and vertical padding.
- Use a readable font size and medium font weight.
- Include subtle hover and focus effects.
- Make the entire button clickable, not just the arrow.
- Maintain consistent spacing between the back button, OnSpot logo, and form heading.
- Ensure it is accessible and responsive on mobile devices.

Suggested appearance:

**← Back to Portal**

Use the existing OnSpot design system, colors, and typography. Do not redesign the entire form.

### 5. Apply Consistently Across Authentication Pages

Ensure the updated navigation and back button design are implemented consistently across:

- Talent Login
- Talent Sign Up
- Client Login
- Client Sign Up
- Client/Talent portal selection screen

Reuse a shared back button component where appropriate to maintain consistent styling and behavior.

### 6. Preserve Existing Functionality

Do not modify or break:

- Login and registration authentication logic
- LinkedIn or other social login integrations
- Password validation
- Form fields and validation messages
- Existing Client/Talent account flows
- Authentication redirects after successful login or registration
- Other unrelated website pages or components

The new previous-page navigation should apply when users cancel or leave the authentication flow, not override successful authentication behavior.
