## Goal

Add support for **Draft / Unfinished Job Postings** for **both Admin and Client**.

Both Admin and Client use the Job Posting Form / `JobFormPage`, so draft functionality must work consistently for both roles.

A draft represents a job posting where the user started filling out the multi-step Job Posting Form but has **not completed/submitted the full posting yet**.

The user must be able to:

1. Start creating a job.
2. Fill out one or more steps.
3. Leave the form using **Save & exit**.
4. Save the partially completed form as a Draft.
5. See that Draft from the appropriate Admin or Client Jobs dashboard.
6. Click **Continue Editing** / **Resume**.
7. Return to the Job Posting Form anytime with all previously entered information restored.
8. Finish the remaining steps and submit normally.

## 1. Draft status

Extend the existing job posting status/data model rather than creating a separate draft system.

Use an appropriate status such as:

```ts
draft
```

Preserve all existing statuses and existing approval/open/closed behavior.

A Draft:

* is unfinished
* is editable
* may contain incomplete data
* must NOT require all normal publishing/submission validation
* must NOT appear in the public **Find Work** page
* must NOT appear in worker/candidate job searches
* must NOT count as Open
* must NOT count as Pending Approval
* must NOT be treated as Approved
* must NOT trigger normal job approval/publication workflows

Only completed/submitted jobs should enter the existing approval/publication workflow.
