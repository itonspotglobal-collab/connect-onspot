# TASK: Client Account Navigation Improvement — Dedicated Job Postings and Job Submissions Pages

## Project
OnSpot / `connect-onspot`

## Objective

Improve the Client Account navigation and user experience by creating two dedicated pages:

1. **Job Postings**
2. **Job Submissions**

Currently, Clients can only access their Job Postings and Job Submissions through the Client Profile page.

We want these features to be directly accessible through the sidebar under **Core Modules**.

Since both features will have their own dedicated pages, the Client Profile should display only a summarized preview of each section instead of the full management interface.

**Important: This is primarily a frontend navigation and UI restructuring task. Preserve all existing backend functionality, database records, permissions, and hiring workflows.**

---

- Client sidebar navigation
- Client Profile page
- Job Postings section
- Job Submissions section
- Existing Client job management endpoints
- Application details and status update functionality
- Client permissions and organization ownership rules

Identify the existing components, API endpoints, and reusable logic.

Reuse existing components and functionality wherever possible.

Do not create duplicate backend workflows or independent copies of the same business logic.

Keep all existing Management and System navigation items unchanged.

- Follow the existing sidebar design and styling.

- Support collapsed sidebar behavior if implemented.
- Support mobile and tablet navigation.

### Job summary

Preserve existing actions:

- Invite Talent

- Preserve existing job creation and editing flows.

- Do not expose other Clients' jobs.

- Make the page responsive.

When a Client clicks **View**, open the existing job details experience.

Do not create a new job details system if one already exists.

## 4. Create a Dedicated Job Submissions Page

Create a separate **Job Submissions** page accessible through the Client sidebar.

Move or reuse the existing Job Submissions section currently displayed inside Client Profile.

### Page header

Title: **Job Submissions**

Description: "Review and manage applications submitted to your job openings."

### Summary information

Display:

- Total Applications
- New Applications
- Under Review
- Shortlisted
- Rejected

Use the application's actual canonical status values and mappings.

Avoid counting the same application more than once.

### Application listing

Display the Client's eligible job applications.

Each application should show:

- Applicant display name
- Applied position
- Application date
- Current application status
- Available actions

Preserve existing actions:

- View Application
- Message Talent, when permitted
- Change Application Status, when permitted

### Search and filtering

Add or preserve:

- Search by applicant name or job title
- Filter by job posting
- Filter by application status
- Sort by newest or oldest application

Use server-side pagination or the existing pagination approach where appropriate.

### Important: Preserve Automatic Status Emails

The application status automation was recently updated.

Clients can now change eligible application statuses without Admin approval.

When a Client changes an eligible application status:

1. Validate the requested transition.
2. Automatically select the appropriate existing email template.
3. Send the corresponding email to the Talent.
4. Complete the application status transition according to the existing email delivery and recovery rules.
5. Update the Talent-facing application status and notifications.

Do not reintroduce Admin approval.

Do not open a manual email composer.

Do not create a second status update API.

**Reuse the exact existing status update endpoint and automatic email implementation.**

Preserve duplicate-email prevention, failure handling, retry safety, and status history.

### Privacy and workflow restrictions

- Preserve masked Talent information.
- Do not expose restricted contact details.
- Show only applications the Client is authorized to access.
- Do not mix private Search-to-Shortlist records with actual job applications.
- Preserve existing interview, offer, contract, and hiring workflow restrictions.

## 5. Simplify the Client Profile Page

Since Job Postings and Job Submissions will now have dedicated pages, the Client Profile should no longer display their complete management interfaces.

Instead, convert both sections into compact summary previews.

### Job Postings preview

Display:

- Section title: Job Postings
- Total number of jobs
- Open jobs count
- Pending jobs count
- A preview of the 3 most recent job postings

Each preview may show:

- Job title
- Current status
- Date

Include a clearly visible:

**View All Job Postings →**

This button should navigate to the new Job Postings page.

### Job Submissions preview

Display:

- Section title: Job Submissions
- Total number of applications
- New applications count
- Shortlisted applications count
- A preview of the 3 most recent applications

Each preview may show:

- Applicant display name
- Applied position
- Current status

Include:

**View All Submissions →**

This button should navigate to the new Job Submissions page.

### Profile simplification rules

Remove the full job listing and full application table from Client Profile.

Remove full management controls from the preview sections, except navigation to the appropriate dedicated pages.

Keep the Client's existing profile information, company details, and other unrelated profile functionality unchanged.

The Client Profile should function as a profile overview, not the primary job management workspace.
