# IMPORTANT PRODUCT DIRECTION

We are using Microsoft 365 / Outlook as the email/calendar provider.

The Interviewer should be tied to a real Microsoft 365 user or Microsoft Bookings staff member.

The eventual flow should be:

```text
Choose interviewer
        ↓
Choose date range + duration + timezone
        ↓
OnSpot asks Microsoft for that interviewer's free/busy schedule
        ↓
Only available interview slots are shown
        ↓
Admin selects a slot
OR
Talent is allowed to choose from those available slots
```

Do NOT ask users to manually type their availability.

Do NOT let OnSpot offer calendar times that conflict with the selected interviewer's Outlook calendar.

# PART 4 — OUTLOOK / MICROSOFT AVAILABILITY

# =====================================================

Implement this behind the backend.

Do NOT call Microsoft Graph directly from the browser using secrets.

Create server-side Microsoft Graph integration.

---

# AVAILABILITY OPTION A — OUTLOOK GETSCHEDULE

Microsoft Graph supports:

```text
POST /users/{id|userPrincipalName}/calendar/getSchedule
```

Use this to retrieve free/busy information from the selected interviewer's Outlook calendar.

Least-privilege application permissions should be reviewed carefully.

Conceptual request:

```json
{
  "schedules": [
    "jane.smith@onspotglobal.com"
  ],
  "startTime": {
    "dateTime": "2026-08-28T09:00:00",
    "timeZone": "Asia/Manila"
  },
  "endTime": {
    "dateTime": "2026-08-30T18:00:00",
    "timeZone": "Asia/Manila"
  },
  "availabilityViewInterval": 30
}
```

Use actual Microsoft-compatible timezone handling.

---

# AVAILABILITY OPTION B — MICROSOFT BOOKINGS

If a shared Microsoft Bookings business is configured, Microsoft Graph supports:

```text
POST /solutions/bookingBusinesses/{businessId}/getStaffAvailability
```

This accepts:

* staff IDs
* start range
* end range

and returns staff availability.

If Bookings is the chosen final integration, map each OnSpot interviewer to:

`bookingsStaffId`.

---

# RECOMMENDATION

Structure the backend so availability comes through an abstraction:

```ts
getInterviewerAvailability(...)
```

For example:

```ts
getInterviewerAvailability({
  interviewerUserId,
  startDate,
  endDate,
  timezone,
  durationMinutes
})
```

Then internally it can use:

* Bookings staff availability
  OR
* Outlook getSchedule

without coupling the frontend to Microsoft API details.
