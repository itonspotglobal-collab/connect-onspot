# Fix HTTP 413 – Talent Profile Video Upload Failure

## Issue

A Talent account is unable to upload a video introduction under the Talent Profile page.

**Actual error:**
- Upload Failed
- Request failed with status code 413
- The uploaded video is only 63 MB.

The system must support legitimate video uploads within its intended size limit without failing due to request body or infrastructure restrictions.

## Existing codebase

GitHub repository: `itonspotglobal-collab/connect-onspot`

Relevant files identified:
- `client/src/pages/TalentProfile.tsx`
- `client/src/pages/ProfileSettings.tsx`
- `server/routes/candidateMedia.ts`
- `server/routes.ts`

Existing endpoint:
`POST /api/candidates/:id/video`

The existing candidate media route checks a maximum video size of 200 MB, but the request is processed by Multer before this validation runs.

**Important:** The same upload endpoint is used by Talent Profile and Profile Settings. Fix both interfaces without breaking either.

## Required tasks

### 1. Investigate the root cause

Trace the entire video upload flow:

Talent Profile → frontend FormData → API endpoint → Multer middleware → storage service → database update.

Check:
- Multer's actual configured `fileSize` limit in `server/routes.ts`.
- Whether resume and video uploads share a smaller global limit.
- Any proxy, CDN, Replit deployment, or hosting request-body restrictions.
- Whether the upload is rejected before Express receives the request.
- Storage provider limits.
- Any global request middleware affecting multipart uploads.

Use logs and response headers to determine which layer returns HTTP 413. Do not assume Multer is the cause without confirming it.

### 2. Fix video uploads up to 200 MB

The current candidate video endpoint already enforces a 200 MB maximum.

Ensure that the complete upload flow supports valid videos up to this limit.

If Multer has a smaller configured limit, correct it without unnecessarily increasing limits for unrelated routes.

If the hosting provider rejects large requests before they reach Express, implement a supported direct-to-object-storage or resumable upload approach rather than simply increasing an Express limit.

Do not use Base64 encoding to transfer videos.

Avoid unnecessarily buffering 200 MB video files entirely in server memory. Prefer streaming or direct storage uploads where supported.

Maintain server-side file validation and safe upload limits.

### 3. Preserve existing functionality

Ensure the following continue working:

- Talent video upload
- Talent Profile video playback
- Video replacement
- Video deletion
- Profile Settings video upload
- Profile Settings video playback
- Existing video URL and filename persistence
- Candidate authentication and ownership validation

Preserve the existing Candidate database fields:

- `videoIntroUrl`
- `videoIntroFileName`

Do not modify unrelated profile, resume, job application, or authentication functionality.

### 4. Improve frontend upload handling

Update both `TalentProfile.tsx` and `ProfileSettings.tsx`.

Requirements:
- Validate the file size before starting the upload.
- Show a clear message for videos larger than 200 MB.
- Display an uploading indicator and progress percentage where technically supported.
- Prevent duplicate uploads while one is in progress.
- Display meaningful errors instead of a generic failed request message.
- Handle HTTP 413 gracefully.
- Refresh candidate data after a successful upload.
- Maintain existing video recording functionality.

Suggested error message for oversize videos:

"Your video exceeds the 200 MB limit. Please upload a smaller video."

For server or infrastructure failures, display a more appropriate message without falsely blaming the user's file.

### 5. Improve backend error handling

Return consistent JSON error responses for:
- File too large (413)
- Unsupported video format (400 or 415)
- Unauthorized upload (401/403)
- Missing file (400)
- Storage upload failure (appropriate 5xx response)

Ensure Multer errors are caught and correctly handled.

Do not expose internal infrastructure details, secrets, or stack traces to the frontend.

Ensure failed uploads do not update the candidate's video metadata or leave unnecessary orphaned objects.

### 6. Verify storage and deployment compatibility

Check the actual storage implementation.

If direct-to-storage uploads are necessary:
- Use the application's existing storage provider.
- Generate appropriately scoped, short-lived upload authorization.
- Validate ownership, file type, and file size.
- Only save the database URL after successful upload verification.
- Preserve secure access to existing videos.
- Avoid introducing public write access.

Do not add a new storage provider unless absolutely necessary.

### 7. Testing

Test the following scenarios:

| Scenario | Expected result |
|---|---|
| 5 MB video | Upload succeeds |
| 30 MB video | Upload succeeds |
| 63 MB video | Upload succeeds |
| 100 MB video | Upload succeeds |
| 200 MB video | Upload succeeds within the documented limit |
| Over 200 MB video | Clear validation error |
| Unsupported file | Rejected appropriately |
| Unauthenticated upload | Rejected |
| Another candidate's profile | Access denied |
| Replace existing video | Successful |
| Delete existing video | Successful |
| Refresh after upload | Video remains available |

Test both Talent Profile and Profile Settings.

If the deployed environment cannot support the intended limit, document the restriction and implement a compatible upload solution rather than reporting success based only on local tests.
