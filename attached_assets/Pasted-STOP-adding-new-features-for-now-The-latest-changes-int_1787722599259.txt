# REGRESSION 1 — Client-created jobs incorrectly show APPROVED before Admin approval

This must be fixed first.

Current observed behavior:

Client creates a job using:

```text
Submit for Approval
```

Admin correctly sees that same job as:

```text
PENDING
```

but the Client Profile incorrectly displays:

```text
OPEN
APPROVED
```

for the same job.

Therefore do NOT change the backend approval workflow unless investigation proves it is broken.

The screenshots indicate the Admin side still knows the job is pending.

## Known suspicious code

Inspect:

```text
client/src/pages/ClientProfile.tsx
```

Current code contains logic equivalent to:

```ts
const approvalStatus = (job as any).approvalStatus ?? "approved";
```

This is unsafe.

A missing or differently named approval field must NEVER automatically mean "approved".

Remove the `"approved"` fallback.

First inspect the actual shape returned by:

```text
GET /api/client/jobs
```

Determine whether the API returns:

```text
approvalStatus
```

or:

```text
approval_status
```

or another canonical field.

Use the actual backend value.

Preferred robust behavior:

```ts
const approvalStatus =
  job.approvalStatus ??
  job.approval_status ??
  "pending";
```

ONLY use the snake/camel fallback if both shapes genuinely exist in this codebase.

Ideally normalize the API response to one canonical field instead.

## Required state behavior

Immediately after a Client submits a new job:

Client Profile must show:

```text
OPEN
PENDING APPROVAL
```

and:

```text

```

The job must NOT appear on the public Find Work job board.

```text
OPEN

```

Only then may it appear publicly.

Client Profile must show:

```text

```

## Preserve Submit for Approval

Do NOT remove or bypass:

```text

```

The expected lifecycle remains:

```text

      ↓

      ↓

      ↓

```

Do not auto-approve Client-created jobs.

Do not make `status = open` synonymous with `approval = approved`.

These are separate concepts:

```text

pending / approved / rejected / linked_to_existing
```

Keep them separate.
