# CHAT / MESSAGES

This needs special handling.

Do NOT send an email for every single chat message immediately.

That will cause notification spam.

Instead implement a safe email-notification policy around the existing chat system.

Preferred V1:

If recipient is not actively viewing the conversation / has not read messages within an appropriate short window:

send one email notification for unread activity.

Example:

Subject:
`New message on OnSpot`

Body:

`You have a new message from [display name].`

Optional short sanitized preview.

CTA:
`View Message`

Do not include sensitive message contents by default if there are privacy concerns.

Do NOT send multiple emails for five messages sent within a minute.

Use thread/user-level deduping or cooldown.

Suggested rule:

one unread-message email per thread/recipient within a configurable window, such as 10–15 minutes.

Do not use process-local setTimeout for persistence-critical behavior.

If the existing system has no scheduler/queue, use event-based deduping:

first unread message
→ email

later unread messages
→ no new email until prior email state/reset condition is cleared.

When recipient reads the thread, allow a future unread email again.

Audit existing read/unread state first.
