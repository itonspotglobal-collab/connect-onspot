## Fix Talent Application Flow for Client-Created Jobs

Work inside the existing **OnSpot / connect-onspot** codebase.

### Problem

There is a bug in the Talent **Find Work** application flow.

Current reproduction:

1. Log in using a **Client** account.
2. Create a job from the Client portal.
3. Log in using an **Admin** account.
4. Approve the client-submitted job.
5. Log in using a **Talent** account.
6. Open **Find Work**.
7. Open the approved job.
8. Click **Apply Now**.

Instead of opening the existing internal job application form, the user is taken to a page that says:

> This job uses an external application
> Please use the Apply Now link on the job listing.

This is incorrect for normal client-created jobs.

### Expected behavior

The account that created the job must **not** determine whether the job uses an internal or external application.

An approved client-created job should behave exactly like an admin-created job.

Application behavior must depend only on the job's configured application method:

* `applicationMethod === "built_in_form"` → open the existing internal application form.
* `applicationMethod === "external_link"` AND a valid `applyLink` exists → open the external URL.
* A client-created job must **not automatically become an external application** simply because its source/creator is a client.

For a built-in application, clicking **Apply Now** should navigate to:

```tsx
/jobs/${job.id}/apply
```

and load the existing:

```text
client/src/pages/JobApplyPage.tsx
```

Do not create a second application form.

## 2. Do not use job source/creator as the application method

Remove or correct logic equivalent to:

```tsx
if (job.source === "client") {
  // treat as external
}
```

or:

```tsx
if (job.clientId) {
  // external application
}
```

or:

```tsx
if (job.createdByClient) {
  // external
}
```

or any similar condition.

The following fields must NOT independently determine the application flow:

```text
source
createdBy
created_by
clientId
client_id
creator role
```

A client-created job can use the built-in OnSpot application form.

---

## 3. Use applicationMethod as the source of truth

Normalize application behavior around the existing values:

```ts
type ApplicationMethod =
  | "built_in_form"
  | "external_link";
```

Expected application logic:

```tsx
const applicationMethod = job.applicationMethod;

if (applicationMethod === "external_link" && job.applyLink) {
  window.open(job.applyLink, "_blank", "noopener,noreferrer");
  return;
}

navigate(`/jobs/${job.id}/apply`);
```

The built-in form should be the normal/default path.

Do not send the talent to an external-application informational page when:

```ts
job.applicationMethod === "built_in_form"
```

## 4. Fix defaults for client-created jobs

Inspect the Client job creation flow.

A normal job created from the Client portal should default to:

```ts
applicationMethod: "built_in_form"
```

unless the client explicitly selected an external application method.

If there is no UI option allowing the client to choose an external application URL, then client-created jobs should always default to:

```ts
applicationMethod = "built_in_form"
applyLink = null
```

Do not infer:

```ts
applicationMethod = "external_link"
```

just because the job came from the Client portal.

Check both:

* frontend payload construction
* backend/default/database insertion logic

The backend should enforce a safe default even if the frontend omits the field.

Example:

```ts
applicationMethod:
  body.applicationMethod === "external_link"
    ? "external_link"
    : "built_in_form";
```

## 9. Handle bad external configuration safely

If:

```ts
applicationMethod === "external_link"
```

but:

```ts
applyLink
```

is null, empty, or invalid, do not send the user to a dead-end informational screen.

Prefer a clear disabled/error state such as:

```text
Application link unavailable
```

Do not silently fall back to external behavior.

For:

```ts
applicationMethod === "built_in_form"
```

the absence of `applyLink` is completely normal.

## 11. Database/backfill check

Inspect existing client-created jobs in the database.

If historical client jobs were incorrectly saved as:

```text

```

despite having no `applyLink`, add a safe migration/backfill if appropriate.

For example, conceptually:

```sql
UPDATE jobs
SET application_method = 'built_in_form'
WHERE source = 'client'
  AND (
    apply_link IS NULL
    OR TRIM(apply_link) = ''
  )
  AND application_method = 'external_link';
```

Adapt this to the actual schema and database naming.

Do NOT blindly rewrite legitimate external-link jobs that actually have a configured external application URL.
