Update the job posting system so job openings can follow a structured role taxonomy similar to this:

- Professional Role Name
- Original Role / Alternative Role Name
- Function

Example:

Professional Role Name:
Senior Account Executive – Salesforce Solutions

Original Role / Alternative Role:
Account Executive / Business Development Representative

Function:
Sales

Goal:
Admins and clients should be able to enter a polished public-facing role title, preserve the original/internal role title, and assign the job to a broader business function.

This should work in:
- Add New Job Posting
- Edit Job Posting
- Admin Find Work page
- Client Profile job submission
- Pending approval review
- Find Work job cards
- Job details popup
- Full job details page
- Search and filtering

1. Update the shared job schema

Add these fields to the shared Job type/schema:

```ts
professionalRoleName: string;
originalRoleName?: string | null;
jobFunction: string;

Field meaning:

professionalRoleName
The polished public-facing title shown to candidates.

originalRoleName
The original, internal, client-provided, legacy, or alternative job title.

jobFunction
The broader functional group used for organization and filtering.

Examples:

{
  professionalRoleName:
    "Senior Account Executive – Salesforce Solutions",

  originalRoleName:
    "Account Executive / Business Development Representative",

  jobFunction:
    "Sales"
}

Keep the existing title field temporarily for backward compatibility.

Preferred compatibility behavior:

title = professionalRoleName

Do not remove the existing title column until all current pages and API routes have migrated.

payload.professionalRoleName =
  formData.professionalRoleName.trim();

  formData.originalRoleName.trim() || null;

Keep title and category synchronized temporarily so current public pages, filters, and APIs do not break.

Update the database

Add columns safely without deleting existing jobs.

Suggested PostgreSQL migration:

ALTER TABLE jobs
ADD COLUMN IF NOT EXISTS professional_role_name TEXT;

ALTER TABLE jobs
ADD COLUMN IF NOT EXISTS original_role_name TEXT;

ALTER TABLE jobs
ADD COLUMN IF NOT EXISTS job_function TEXT;

Backfill existing jobs:

UPDATE jobs
SET professional_role_name = title
WHERE professional_role_name IS NULL
   OR professional_role_name = '';

UPDATE jobs
SET job_function = category
WHERE job_function IS NULL
   OR job_function = '';

After backfilling, make required fields non-null only if appropriate:

ALTER TABLE jobs
ALTER COLUMN professional_role_name SET NOT NULL;

ALTER TABLE jobs
ALTER COLUMN job_function SET NOT NULL;

Do not drop the existing title or category columns yet.

Important constraints

Store Professional Role Name, Original Role Name, and Function separately
Do not make Function a fixed dropdown
Do not delete the existing title/category fields yet
Do not break current job postings
Use a non-destructive database migration

The ideal structure is:

| Field | Purpose |
|---|---|
| **Professional Role Name** | Clean public-facing title |
| **Original Role / Alternative Role** | Client’s original or commonly used title |
| **Function** | Broad organizational and filtering group |

This will let you maintain professional titles while still preserving the wording clients originally submitted.
