# 2. Homepage Hero — General Mobile Rules

The homepage uses a 5-slide hero carousel.

The desktop version uses a fixed viewport-oriented composition and should stay that way.

On mobile, however, slides 2–5 currently stack their content vertically and the mockups/cards become too tall. This causes the carousel navigation controls at the bottom to be pushed below the visible viewport or clipped.

Fix this specifically for mobile.

## Mobile hero requirements

For screens below roughly `768px`:

* All important slide content must remain inside the visible hero area.
* The bottom carousel controls must be visible on **every slide**.
* The previous, play/pause, next, slide counter, and progress dots must never be hidden behind a mockup.
* Do not allow tablet/phone/card mockups to push the controls outside the viewport.
* Prevent horizontal overflow.
* Avoid text being clipped underneath the navbar.
* Keep enough breathing room between navbar, heading, CTA, visual mockup, and carousel controls.
* Maintain swipe behavior and existing carousel logic.
* Maintain auto-advance logic.
* Keep the current desktop hero height/layout intact.

You may introduce a mobile-specific hero height/min-height strategy if necessary.

For example, it is acceptable on mobile to use a controlled layout such as:

* hero content area as a flex column
* text block taking only the space it needs
* visual/mockup area constrained with a responsive `max-height`
* controls reserved at the bottom using `flex-shrink-0`

Do not simply hide the controls.

Do not solve this by giving the page an enormous arbitrary height.

# 13. Preferred Implementation Approach

Please favor responsive classes instead of JavaScript viewport checks.

Examples:

* `max-md:*`
* `sm:*`
* `md:*`
* `lg:*`

or scoped CSS media queries.

Avoid using `window.innerWidth` for layout styling unless unavoidable.

For visual/mockup sizing, prefer responsive CSS such as:

* `width`
* `max-width`
* `max-height`
* `transform: scale(...)`
* `transform-origin`
* flex/grid alignment
* overflow clipping in a deliberate visual wrapper

instead of hardcoding coordinates.
