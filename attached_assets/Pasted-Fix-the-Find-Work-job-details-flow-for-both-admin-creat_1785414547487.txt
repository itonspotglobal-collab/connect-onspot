Part 4: Use a public single-job endpoint



Do not fetch every admin job from:



/api/admin/jobs



to render a public job details page.



Create or use a public endpoint such as:



GET /api/jobs/:id



This endpoint should:



return one approved/open public job by ID

support jobs created by admins

support jobs submitted by clients and later approved

return 404 only when the job does not exist or is not publicly available



Suggested frontend query:



const {

  data: dbJob,

  isLoading,

  isError,

  error,

} = useQuery<Job>({

  queryKey: ["/api/jobs", rawId],

  queryFn: async () => {

    const res = await fetch(`/api/jobs/${encodeURIComponent(rawId)}`);



    if (res.status === 404) {

      throw new Error("Job not found");

    }



    if (!res.ok) {

      throw new Error("Failed to load job");

    }



    return res.json();

  },

  enabled: Boolean(rawId) && !isStaticId,

});



Do not require an authenticated admin endpoint for a public job-details page.



Part 5: Standardize job visibility rules



Create one reusable public visibility rule.



A job should be publicly visible only when:



approval status is approved

job status is open/published

it has not been deleted



Example helper:



function isPublicJob(job: Job) {

  const approved =

    job.approvalStatus === "approved" ||

    job.approvalStatus == null;



  const open =

    job.status === "open" ||

    job.status === "published";



  return approved && open && !job.deletedAt;

}



Adapt the exact values to the project schema.



Use the same rule in:



public jobs list

Find Work live preview

Find Work search/results

single-job details endpoint



Do not let the list page show a job that the details endpoint rejects.
