# CURRENT BUG

The Client sidebar still looks visually cut/broken when the blue `TopNavigation` hides while scrolling down.

The TopNavigation:

* is fixed at the top
* hides by translating upward while scrolling down
* returns when scrolling upward

The Client sidebar uses the shared ShadCN Sidebar implementation which is itself positioned as a fixed viewport element.

This causes the sidebar and TopNavigation to use incompatible positioning systems.

The result is the sidebar looking:

* clipped
* cut at the top
* detached
* incorrectly sized
* visually broken when the header hides

Do not solve this with more scroll animation.

# GOAL

The Client sidebar should look like ONE continuous sidebar column regardless of whether TopNavigation is visible or translated offscreen.

It must never appear visually cut.

# IMPORTANT DESIGN DECISION

Do NOT move or animate the sidebar when TopNavigation hides.

Instead:

* keep the sidebar's viewport column/background continuous
* reserve the navigation height for the sidebar CONTENT
* let TopNavigation overlay the top part of the sidebar column when visible

Conceptually:

```text
TOP NAV VISIBLE:

┌─────────────────────────────┐
│ TopNavigation               │
├──────────┬──────────────────┤
│ Sidebar  │ Main content     │
│ content  │                  │
│          │                  │


TOP NAV HIDDEN:

┌──────────┬──────────────────┐
│ sidebar  │ main page        │
│ bg       │                  │
│──────────│                  │
│ Sidebar  │                  │
│ content  │                  │
```

There should not be a white/transparent broken strip.

---

# BEST FIX: FULL-HEIGHT SIDEBAR BACKGROUND + CONTENT OFFSET

The sidebar COLUMN may stay:

```text
top: 0
bottom: 0
height: 100svh
```

so its background fills the entire left edge.

But the navigational CONTENT should begin below:

`var(--nav-h)`

on desktop.

This is preferable to making the entire sidebar begin below the header.

Why:

If the full sidebar itself starts at:

```text
top: var(--nav-h)
```

then when TopNavigation hides, a visible empty gap remains above the sidebar.

That is exactly the visual problem we want to eliminate.
