Improve the Jobs Admin list so users can clearly navigate through all posted jobs instead of older jobs appearing to disappear when more than 25 exist.

## Current issue

The Jobs Admin list shows a maximum of 25 jobs.

When there are exactly 25 jobs and a new job is added:

```text
Before:
25 jobs

After adding "Test":
still only 25 visible jobs
```

The new job appears at the top, but the oldest job disappears from the bottom.

This is confusing because there is currently no visible pagination/navigation showing that the older job moved to another page.

The correct behavior should be:

```text
26 total jobs

Page 1:
newest 25 jobs

Page 2:
oldest 1 job
```

No job should be deleted, replaced, or permanently hidden.

---

# Add visible pagination controls

At the bottom of the Admin Jobs list, add a pagination section similar to a standard data table.

Example for 26 jobs:

```text
Page 1 of 2

25 per page

First   ← Previous   1   2   Next →   Last
```

Example for 100 jobs:

```text
Page 1 of 4

25 per page

First   ← Previous   1   2   3   4   Next →   Last
```

Example when currently on Page 3:

```text
Page 3 of 4

25 per page

First   ← Previous   1   2   [3]   4   Next →   Last
```

The currently selected page must be visually highlighted.

---

# Page size

Use:

```ts
const PAGE_SIZE = 25;
```

The page size should remain 25.

Do NOT increase the API page size to avoid pagination.

The correct behavior is:

```text
Total jobs = unlimited
Visible jobs per page = 25
```

---

# Pagination state

In:

```text
client/src/pages/AdminFindWork.tsx
```

add:

```ts
const PAGE_SIZE = 25;
const [currentPage, setCurrentPage] = useState(1);
```

The API request should use:

```ts
/api/admin/jobs?page=${currentPage}&pageSize=${PAGE_SIZE}
```

The React Query key must include the page:

```ts
queryKey: [
  "/api/admin/jobs",
  {
    page: currentPage,
    pageSize: PAGE_SIZE,
    tab: activeTab,
  },
]
```


Frontend:

```ts
const jobs = data?.items ?? [];
const currentPage = data?.meta?.page ?? 1;
const totalPages = data?.meta?.totalPages ?? 1;
const totalJobs = data?.meta?.total ?? 0;
```

Use the project's existing button/component styles instead of introducing a new design system.

Calculation:

```ts
const startItem =

  currentPage * PAGE_SIZE,

);
```

# Keep pagination visible

Do not hide pagination simply because the current page contains exactly 25 items.

Display pagination based on:

```ts
totalPages > 1
```

NOT:

```ts
jobs.length > 25
```

Because `jobs.length` can never exceed 25 on a paginated page.

This distinction is critical.

Wrong:

```ts
if (jobs.length > 25)
```

Correct:

```ts
if (data.meta.totalPages > 1)
```

# Important

The desired UX is similar to a standard paginated grid/table:

```text
Page 1 of 4      25 per page

First   ← Previous   [1] 2 3 4   Next →   Last
```

The key requirement is:

**Adding a new job must push older jobs to the next page, not make them appear deleted or lost.**

Do not consider this complete until the 26th job is visibly accessible on Page 2.
