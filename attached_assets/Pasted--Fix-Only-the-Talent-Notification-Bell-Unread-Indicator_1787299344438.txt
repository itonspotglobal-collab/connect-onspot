# Fix Only the Talent Notification Bell Unread Indicator

We already fixed the Admin → Talent application-status notification flow.

## Current state

The actual notification is now working correctly.

When Admin changes a Talent's Job Application status:

* the application status updates correctly
* the notification record is created correctly
* the Talent can open the notification bell
* the new `job_application_status_changed` notification appears correctly

Example currently visible in the Talent notification dropdown:

```txt
Application Status Updated

Your application for Customer Service Representative at OnSpot is now reviewed.

Just now
```

However, there is one remaining issue:

**The red unread indicator dot on the notification bell does not appear even though there is a new unread notification.**

This task is ONLY to fix the unread indicator/count behavior.

# Primary debugging objective

Determine why this situation occurs:

```txt
GET /api/talent/notifications
→ returns the new job_application_status_changed notification
```

but:

```txt
GET /api/talent/notifications?unread_only=true
→ causes the unread count to become 0
```

or otherwise results in the React hook returning `0`.

Inspect the actual server implementation of:

```txt
GET /api/talent/notifications
```

especially how this query parameter is handled:

```txt
unread_only=true
```

Check for issues such as:

```ts
req.query.unread_only
```

being interpreted incorrectly.

For example, remember Express query parameters are strings.

Correct handling should be explicit, such as:

```ts
const unreadOnly = req.query.unread_only === "true";
```

Do NOT assume:

```ts
Boolean(req.query.unread_only)
```

or other inconsistent parsing is correct without checking the existing implementation.
