# PRODUCT MODEL

There are TWO different interview actions depending on account role.

## Admin

Admin can initiate:

`Schedule Interview`

This will eventually connect to Microsoft Bookings.

## Client

Client cannot directly schedule the Talent.

Client instead initiates:

`Request Interview`

This will eventually send an Interview Scheduling Request to Admin for approval/action.

Keep these two concepts clearly separate.

---

# EXISTING PIPELINE RULE

The canonical application status:

`interviewing`

already exists.

It is a pipeline-driven state.

Do NOT add `Interviewing` as a normal manual status option.

Later, when a real interview record is successfully created, the system will automatically move the application to:

`interviewing`.

For this UI-only phase, do not change status.

# CLIENT — DO NOT REUSE STATUS REQUEST

through the existing Client Status Change Request workflow.

```text

        ↓

        ↓

        ↓

        ↓

```
