# Problem

The Client Team Dashboard can display modern signed hires, but some dashboard metrics still appear to rely on the legacy time-tracking model.

In particular, weekly hours and recent activity may still read from the legacy:

`time_entries`

while modern billing/time tracking uses data such as:

`clock_sessions`

and/or:

`timesheet_revisions`

This can result in a modern hired Talent appearing correctly on the Client Team Dashboard while showing:

- `0` weekly hours,
- missing hours,
- incomplete activity,
- or inconsistent dashboard information

even when the Talent has legitimate modern clock/timesheet activity.

The objective is to determine the correct source of truth and propose the safest fix.

Do NOT simply replace `time_entries` with another table without tracing the full data model.

# PHASE 8 — CHECK FOR MIXED LEGACY/MODERN HIRES

---

# PHASE 9 — DETERMINE THE CORRECT FIX STRATEGY

After completing the audit, recommend one of these strategies or another evidence-supported strategy:

### Strategy A — Replace legacy source

Use the modern data source exclusively.

Only recommend this if legacy `time_entries` no longer represent legitimate active engagements.

### Strategy B — Merge legacy + modern

Use legacy data for legacy engagements and modern data for modern hiring contracts.

Only recommend this if the systems legitimately coexist and can be reliably distinguished.

### Strategy C — Use canonical timesheet/billing data

Drive dashboard weekly hours from the same finalized source used by modern billing.

This may be preferable if dashboard hours are intended to represent approved/billable hours.

### Strategy D — Different metric semantics

If the dashboard intends to show live/raw worked hours while billing intentionally uses approved hours, document that distinction and recommend the correct raw source.

Do NOT select a strategy based on convenience.

# CRITICAL DOUBLE-COUNTING CHECK

Your proposal must guarantee that the dashboard does not sum two representations of the same work.
