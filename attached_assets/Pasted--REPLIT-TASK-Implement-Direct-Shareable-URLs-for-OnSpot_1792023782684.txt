# REPLIT TASK: Implement Direct Shareable URLs for OnSpot Signup Popups

## Objective

Implement dedicated, shareable URLs for the existing OnSpot signup popups so that clients and talent can access their respective registration forms directly from email invitations, marketing campaigns, and external links.

Currently, users need to navigate through the website and manually open the signup modal.

We want to make this easier by introducing direct URL access.

## 1. Create Three Dedicated Signup Routes

Implement these routes:

**A. `/portal`**
- Display the existing "Get started with OnSpot" popup.
- Include the two existing options:
  - I'm Hiring
  - I'm Looking for Work
- Selecting an option should open the corresponding registration form.
- Preserve the current modal design.

**B. `/signup/talent`**
- Automatically open the existing "Find Work" talent signup popup.
- Do not show the role-selection popup first.
- Use the existing talent registration component and functionality.

**C. `/signup/client`**
- Automatically open the existing client signup popup.
- Do not show the role-selection popup first.
- Use the existing client registration component and functionality.

All routes must work when opened directly in a new browser tab, including when the user has never visited OnSpot before.

## 2. Preserve the Existing Modal Experience

Do not redesign the signup popups.

Maintain:
- Existing dark navy modal styling
- Actual OnSpot logo
- Form fields and validation
- LinkedIn signup functionality where available
- Signup buttons
- Blurred background overlay
- Modal dimensions
- Scrollable form content
- Close (X) button
- Back to Portal navigation

The goal is to add direct URL access, not change the design.

## 3. Display the Correct Background Page

When a user opens a direct signup URL, display the corresponding existing page behind the modal.

For example:

`/signup/talent`
- Render the existing Find Work landing page.
- Automatically display the talent signup modal.
- Blur and dim the background using the existing overlay styling.

`/signup/client`
- Render the existing Hire Talent landing page.
- Automatically display the client signup modal.
- Blur and dim the background.

`/portal`
- Render the existing homepage or designated portal background.
- Automatically display the Client/Talent selection popup.

Do not replace the background with a plain gradient or empty screen.

## 4. URL and Navigation Behavior

Ensure the following behaviors:

**Direct URL Access**
- Opening a signup URL immediately displays the appropriate modal.
- Refreshing the page keeps the correct modal open.
- The routes work even without previous navigation history.

**Close Button**
- When users click X, close the popup.
- For direct signup links, navigate to the corresponding landing page.
- Talent signup closes to Find Work.
- Client signup closes to Hire Talent.
- Portal closes to the homepage.

**Back to Portal**
- Navigate to `/portal`.
- Display the Client/Talent selection popup.

**Browser Navigation**
- Support browser back and forward buttons.
- Keep the displayed modal synchronized with the current URL.
- Avoid unwanted redirects and navigation loops.

Use the existing project's routing framework and established navigation patterns.

## 5. Reuse Existing Signup Components

Do not create duplicate signup forms.

Inspect the existing codebase and identify:
- Signup selection modal
- Talent signup component
- Client signup component
- Existing modal overlay
- Authentication and registration logic

Reuse these components for the new routes.

The original signup buttons throughout the website should continue working.

Where appropriate, update them to use the new routes so signup navigation becomes consistent.

Do not break the current signup flow.

## 6. Support Email Campaign Links

These routes will be used in external campaigns.

Example:

Talent campaign:
`https://onspotglobal.com/signup/talent`

Client campaign:
`https://onspotglobal.com/signup/client`

General campaign:
`https://onspotglobal.com/portal`

Ensure:
- Direct links work for new visitors.
- URLs are shareable and bookmarkable.
- Opening links on mobile works correctly.
- Query parameters such as `utm_source`, `utm_medium`, and `utm_campaign` do not prevent the modal from opening.
- Existing campaign tracking integrations are preserved.

Do not introduce a new analytics service unless already configured.

## 7. Mobile Responsiveness

Ensure the signup popup works correctly on:
- Desktop
- Tablet
- Mobile

The modal should remain readable and usable on smaller screens.

Maintain appropriate scrolling, visible close controls, and accessible form inputs.

## 8. Testing and Verification

Test all three routes independently.

Verify:
1. `/portal` opens the selection popup.
2. `/signup/talent` opens the talent signup popup.
3. `/signup/client` opens the client signup popup.
4. Refreshing each URL preserves the correct popup.
5. Closing a popup navigates correctly.
6. Back to Portal works.
7. Browser back/forward works.
8. Signup submission uses the existing backend.
9. LinkedIn authentication remains functional.
10. All routes work in a new incognito session.
11. Production hosting supports direct loading of nested routes without returning 404.

## Important Restrictions

- Do not redesign the existing modals.
- Do not change the existing registration business logic.
- Do not duplicate signup components.
- Do not change unrelated pages.
- Do not introduce unnecessary new dependencies.
- Preserve existing authentication and validation.
- Ensure the new routes are production-ready.

## Expected Result

Users should be able to click a link from an email campaign and immediately see the correct OnSpot signup popup over its corresponding blurred landing page.

The signup process should be accessible with a single click, making it easier to invite clients and talent to OnSpot.
