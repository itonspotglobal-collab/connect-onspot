Update the **Create Job Opening** and **Edit / Update Job Opening** flows so they use the same revised job form UI and field behavior.

The changes must apply to both:

* Admin create job
* Admin edit job
* Client create job
* Client edit job

Do not update only the create flow. Existing jobs must also render correctly when editing.

## Required changes

### 1. Remove the small OnSpot logo/brand from the job form top bar

In the current job form page, remove the highlighted mini OnSpot logo/brand shown at the top-left of the form header.

Remove the entire branding block, including:

* the colored `O` icon
* the `OnSpot` text

Keep:

* the centered `Post a Job` / `Edit Job Posting` title
* the `Save & exit` action on the right

The header should remain visually balanced after removing the logo.

Do not remove the main application navbar outside of this job form page.

### 2. Work Setup should only allow Remote

Currently the Work Setup field shows:

* Remote
* Hybrid
* Onsite

Change this so the only available option is:

* Remote

Remove both:

* Hybrid
* Onsite

Do not merely hide them with CSS. Remove them from the selectable options and from any related constants or validation used by the create/edit job form.

For new jobs:

```text
location = "Remote"
```

should be the default.

For edit mode:

* Existing Remote jobs should continue to work normally.
* If a legacy job has `Hybrid` or `Onsite`, do not crash the edit page.
* Preserve the existing value until the user saves, or handle the legacy value safely.
* Do not silently overwrite legacy production data just by opening the edit form.

The final create-job UI should display only a single selected chip/button:

```text
Remote
```

Change the Engagement Type choices from:

```text

Lite
```

to the following user-facing labels:

```text

Lite (4 Hours)
```

Important: the database/API values must remain:

```text

Lite
```


in `jobs.engagement_type`.

The display label and stored value must be separated.

```ts

{

  value: "Lite"

```

Example:

```ts

}
```

Use the project's existing constants/helpers if there is already an appropriate place for this.
