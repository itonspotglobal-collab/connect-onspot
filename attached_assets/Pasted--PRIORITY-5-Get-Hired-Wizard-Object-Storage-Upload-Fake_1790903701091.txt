## PRIORITY 5 — Get Hired Wizard: Object Storage Upload + Fake Assessment Result

Work on **Priority 5 only**.

Do not proceed to Priority 6.

This priority addresses two known Get Hired correctness issues:

1. The Get Hired wizard appears to use an incorrect/outdated object-upload API path.
2. The Get Hired assessment UI contains fabricated assessment data, previously identified as approximately **92%** with a **March 2024** completion/result date.

The objective is to make both behaviors truthful and functional without redesigning the entire Get Hired flow.

Use this decision tree.

## Case A — A real assessment backend exists

If the application has a legitimate assessment/result source:

Handle:

- no assessment
- pending assessment
- completed assessment
- failed API request

truthfully.

## Case B — Assessment functionality exists but no result exists yet

or existing product-equivalent wording.

If the existing wizard currently requires the fake assessment state to advance, correct that requirement so fabricated data is not necessary.
