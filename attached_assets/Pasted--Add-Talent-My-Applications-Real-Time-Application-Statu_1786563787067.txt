# Add Talent “My Applications” + Real-Time Application Status Tracking

We want Talent users to be able to see every job they have applied to and the current status of each application.

This must use the SAME application records and status values used by:

```text
/admin/job-applications
```

Do not create a duplicate Talent-only application tracking table or separate status system.

The Talent-facing application status must remain synchronized with whatever Admin updates in the Job Applications page.

---

# Main goals

Implement three connected features:

1. Add a `My Applications` / `Applied Jobs` item to the Talent Profile dropdown.
2. Create a dedicated Talent page that lists:

   * jobs already applied to;
   * current application status;
   * recommended roles;
   * relevant actions.
3. Add an `Applications` section inside the Talent Profile page showing recent applied jobs and statuses.

At the bottom of the Talent Profile Applications section, add:

```text
Browse More Roles
```

which navigates to the existing:

```text
Find Work
```

page.

# 1. Canonical application source

Do NOT create another application history table.

Identify the actual database model used by:

```text

```

For example it may be:

```text
job_submissions
```

or:

```text
job_applications
```

or another existing application table.

Use that existing table as the source of truth.

The relationship should be:

```text
Candidate
    ↓
Application record
    ↓
Job
    ↓
Application Status
```

When Admin changes:

```text
Submitted
→ Under Review
```

the Talent must see:

```text
Under Review
```

from the SAME row.

# 3. Talent applications response

Return enough information for the Talent UI without requiring many separate calls.

Suggested response:

```ts
interface TalentApplication {
  id: string;

  job: {
    id: string;
    title: string;
    companyName: string;
    location?: string;
    workSetup?: string;
    status?: string;
  };

  applicationStatus:
    | "submitted"
    | "under_review"
    | "shortlisted"
    | "interview"
    | "hired"
    | "rejected"
    | "withdrawn";

  submittedAt: string;
  updatedAt: string;

  resume?: {
    id?: string;
    fileName?: string;
  };

  coverLetter?: string | null;
}
```

Use the actual schema fields.

Include only data the Talent is allowed to see.

Do NOT expose:

```text
internal notes
admin-only comments
private recruiter scoring
evaluation notes
other applicants
```

# 19. Real-time / near-real-time status syncing

The user wants status updates to appear when Admin updates `/admin/job-applications`.

The Talent view must read the same DB data.

Do not duplicate or manually synchronize two tables.

For immediate UI refresh, use one of the following based on the existing stack:

### Preferred simple implementation

React Query polling:

```ts
refetchInterval: 15000
```

or around 15–30 seconds.

Also refetch when the window regains focus:

```ts
refetchOnWindowFocus: true
```

This provides near-real-time behavior without adding unnecessary infrastructure.

### If the project already uses WebSocket/SSE

Reuse it.

Do not introduce WebSockets solely for this feature unless necessary.

# 37. Backend query example

Conceptually, the server query should resemble:

```sql
SELECT
  a.id,
  a.status,
  a.submitted_at,
  a.updated_at,

  j.id AS job_id,
  j.title,
  j.location,
  j.status AS job_status

FROM job_applications a

JOIN jobs j
  ON j.id = a.job_id

WHERE a.candidate_id = $1

ORDER BY a.submitted_at DESC;
```

Do NOT copy this blindly.

Use the actual existing table and column names.
