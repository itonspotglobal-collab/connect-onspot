Fix the password input on the standalone /login page.

Bug:
When typing into the Password field, the input loses focus after each character. The user has to click the password field again to type the next character.

Expected behavior:
The user should be able to type the entire password continuously without the field losing focus, refreshing, resetting, or moving the cursor.

This issue appears on the new standalone login page.

Files to inspect:
- client/src/pages/PortalLogin.tsx
- the shared portal login form component, if one was created
- client/src/hooks/usePortalLogin.ts
- client/src/lib/portalAuth.ts
- any reusable authentication form component
- client/src/App.tsx

Likely causes to check:

1. Component declared inside another component

Do not define the login form as a component inside PortalLogin’s render function.

Wrong:

function PortalLogin() {
  const [password, setPassword] = useState("");

  function LoginForm() {
    return (
      <Input
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />
    );
  }

  return <LoginForm />;
}

Because LoginForm is recreated on every PortalLogin render, React may treat it as a new component and remount the input.

Move it outside:

function LoginForm(props: LoginFormProps) {
  return (...);
}

export default function PortalLogin() {
  ...
  return <LoginForm ... />;
}

Or render the form JSX directly without creating a nested component.

2. Changing key on the form or input

Inspect the Password input and its parent containers.

Remove keys such as:

key={password}
key={formData.password}
key={Date.now()}
key={JSON.stringify(formData)}
key={`${email}-${password}`}
key={selectedPortal}
key={location}
key={searchParams.toString()}

A controlled password input must not have a key that changes while typing.

Use a fixed key only when one is genuinely required.

3. Do not rebuild the page based on form state

Do not wrap the login page in conditional JSX that changes the component tree whenever password changes.

For example, avoid:

{password ? <LoginForm ... /> : <LoginForm ... />}

or:

<LoginForm key={password.length} />

Keep the same input instance mounted.

4. Store password state locally

The password should use simple local state:

const [password, setPassword] = useState("");

<Input
  id="portal-login-password"
  name="password"
  type={showPassword ? "text" : "password"}
  value={password}
  onChange={(event) => setPassword(event.target.value)}
  autoComplete="current-password"
/>

Do not:
- write the password to the URL
- update query parameters while typing
- save the password to localStorage
- call navigation while typing
- call refreshAuth while typing
- submit the form from onChange

5. Check URL query parameter synchronization

The page supports query parameters such as:

/login?portal=client
/login?portal=talent

Only read these parameters on page load.

Do not update the URL whenever form state changes.

Wrong:

useEffect(() => {
  setLocation(`/login?portal=${portal}&email=${email}`);
}, [portal, email, password]);

This can trigger route rerenders/remounts while typing.

Only initialize portal/email from the URL once:

useEffect(() => {
  const params = new URLSearchParams(window.location.search);
  const portalParam = params.get("portal");

  if (portalParam === "client" || portalParam === "talent") {
    setPortal(portalParam);
  }
}, []);

Do not include password in that effect.

6. Check useEffect dependencies

Find effects that run when password changes.

Remove password from dependencies unless the effect is only local validation.

Problematic example:

useEffect(() => {
  initializeLoginPage();
  refreshAuth();
}, [password]);

Auth initialization should run once:

useEffect(() => {
  initializeLoginPage();
}, []);

Validation may be calculated without an effect:

const canSubmit =
  email.trim() !== "" &&
  password !== "" &&
  portal !== null;

7. Do not call refreshAuth on every render

If PortalLogin calls refreshAuth(), it should be inside a mount-only effect:

useEffect(() => {
  refreshAuth();
}, []);

Do not call:

refreshAuth();

directly in the component body.

Do not call it inside password onChange.

8. Keep password visibility toggle stable

Use:

const [showPassword, setShowPassword] = useState(false);

The visibility button must have:

type="button"

Example:

<button
  type="button"
  onClick={() => setShowPassword((current) => !current)}
  aria-label={showPassword ? "Hide password" : "Show password"}
>
  ...
</button>

It must not submit or reset the form.

9. Use one stable form element

Recommended structure:

<form onSubmit={handleSubmit}>
  <Input
    id="email"
    value={email}
    onChange={(e) => setEmail(e.target.value)}
    autoComplete="email"
  />

  <Input
    id="password"
    value={password}
    onChange={(e) => setPassword(e.target.value)}
    autoComplete="current-password"
  />

  ...
</form>

Do not replace the entire form while the user is typing.

10. Avoid state updates during render

Do not do this in the component body:

if (!portal && portalFromUrl) {
  setPortal(portalFromUrl);
}

That creates render loops.

Move it to useEffect or useState initialization.

Preferred:

const [portal, setPortal] = useState<PortalType | null>(() => {
  const value = new URLSearchParams(window.location.search).get("portal");
  return value === "client" || value === "talent" ? value : null;
});

11. Check animation wrappers

If the form uses Framer Motion or AnimatePresence:
- Do not use password, email, or portal as the motion component key.
- Use a stable key such as:
  key="login-form"

If switching between login and forgot-password screens, keys may be:
- key="login"
- key="forgot-password"

But the login key must not change while typing.

12. Browser password manager compatibility

The password manager icon shown inside the field is normal and should not cause focus loss.

Use appropriate attributes:

Email:
- name="email"
- autoComplete="email"

Password:
- name="password"
- autoComplete="current-password"

Do not disable password managers unless required.

13. Add a temporary focus test

Temporarily add:

onFocus={() => console.log("[LOGIN] password focused")}
onBlur={() => console.log("[LOGIN] password blurred")}

While typing, the password input should not emit blur after every character.

Also add a temporary mount log inside the form:

useEffect(() => {
  console.log("[LOGIN] form mounted");

  return () => {
    console.log("[LOGIN] form unmounted");
  };
}, []);

If “form unmounted” appears after every keystroke, find and remove the changing component identity or key.

Remove the debug logs after fixing the issue.

14. Preserve existing authentication behavior

Do not change:
- Client login endpoint
- Talent login endpoint
- Client redirect to /client-profile
- Talent redirect to their existing profile
- portal selection
- forgot-password logic
- visual design

This task should only fix the input focus/remount issue.

Acceptance criteria:
- User clicks the Password input once.
- User can type the full password continuously.
- Input does not lose focus after each character.
- Password value does not reset.
- Cursor remains in the input.
- Show/hide password still works.
- Client and Talent login continue working.
- The standalone login page design remains unchanged.
- Email input also remains stable while typing.
- No password is saved to localStorage or URL.
