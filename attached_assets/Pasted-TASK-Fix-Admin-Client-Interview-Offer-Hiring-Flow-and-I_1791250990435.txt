BUG / REQUIREMENT 4
SUPPORT ORGANIC "FIND WORK" APPLICATIONS IN THE FORMAL PIPELINE
============================================================

This is the core architectural fix.

Currently, formalPipelineGuard.ts and related queries heavily restrict
interview/offer/contract operations to:

workflow_type = 'client_invitation'

As a result:

Talent
→ Find Work
→ opens Client job
→ applies
→ Client/Admin sees application
→ Shortlisted
→ Interview/Offer action
→ backend rejects submission

This is incorrect for a legitimate organic application.

A legitimate authenticated Talent who applies to a real approved Client
job through Find Work must be capable of progressing through the same
secure hiring lifecycle.

DO NOT simply delete FORMAL_PIPELINE_PREDICATE.

DO NOT replace it with "allow everything".

DO NOT trust submission IDs supplied by the browser without verifying
ownership/relationships.

Instead, refactor/extend formal pipeline eligibility.

At minimum, formal hiring eligibility should safely support:

A. existing client_invitation flow

AND

B. legitimate organic Find Work application flow

For an organic application verify server-side:
- submission exists
- associated application exists where required
- Talent identity matches the submission/application
- job exists
- job is a real persisted job
- Client owns/is authorized for that job
- organization relationship is valid
- submission belongs to that job
- submission is at an appropriate hiring stage
- submission is not withdrawn/rejected/declined/terminal
- request actor is authorized for the operation

Preserve privacy/name-reveal/security behavior where applicable.

Create a clear reusable eligibility helper rather than duplicating
different insecure checks across Interview, Offer and Contract routes.
