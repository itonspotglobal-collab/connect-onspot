# FIX THE CURRENT RESUME SYNC / REFRESH BUG

You are working inside the existing **OnSpot / connect-onspot** project.

The candidate resume is already being persisted to the correct candidate record, but the frontend synchronization is currently broken.

I tested the current implementation and found these reproducible issues:

### Issue 1 — Talent Profile upload/replace

On the **Talent Profile Page**:

1. An existing resume is displayed.
2. I click **Replace Resume**.
3. The upload starts successfully.
4. After the upload finishes, the attached resume can disappear from the UI.
5. It only reliably appears again after manually refreshing the browser.

This must not happen.

After upload succeeds, the new resume filename should remain visible immediately.

---

### Issue 2 — Profile Settings does not see existing resume

A resume already exists on the candidate and is visible on Talent Profile.

But when opening:

**Talent Profile Settings → Documents**

it displays:

> No resume uploaded yet.

and asks the talent to upload another resume.

This is incorrect.

Talent Profile and Profile Settings belong to the same Candidate and must display the same candidate resume immediately.

---

# ROOT CAUSE TO FIX

Inspect the current code before changing anything.

Currently:

`TalentProfile.tsx`

fetches the candidate using a React Query key similar to:

```ts
["/api/candidates", id]
```

while:

`useCandidateProfileSettings.ts`

fetches the SAME candidate using:

```ts
["candidate-profile", candidateId]
```

with:

```ts
staleTime: 30_000
```

Talent Profile's current resume upload handler only invalidates:

```ts
qc.invalidateQueries({
  queryKey: ["/api/candidates", id],
});
```

It does NOT invalidate:

```ts
["candidate-profile", candidateId]
```

Therefore Profile Settings can continue displaying a stale cached candidate that has:

```ts
resumeUrl: null
resumeFileName: null
```

even though the database candidate already has a resume.

Fix this properly.

```ts
export async function invalidateCandidateQueries(

  await Promise.all([
```

Search the repository first.

# 3. FIX TALENT PROFILE RESUME UPLOAD

Inspect:

```text
client/src/pages/TalentProfile.tsx
```

Current logic effectively does:

```ts
const res = await fetch(`/api/candidates/${id}/resume`, ...);

if (!res.ok) {
  ...
}

  queryKey: ["/api/candidates", id],
});
```

This is not sufficient.

The upload endpoint already returns:

```json
{
  "success": true,
  "resumeUrl": "...",
  "resumeFileName": "Legaspi_CV.pdf"
}
```

USE THAT RESPONSE.

After successful upload:

```ts
const result = await res.json();
```

Immediately update the currently displayed Candidate cache.

Conceptually:

```ts
qc.setQueryData(
  candidateQueryKeys.detail(id),
  (old: Candidate | undefined) =>
    old
      ? {
          ...old,
          resumeUrl: result.resumeUrl,
          resumeFileName: result.resumeFileName,
        }
      : old,
);
```

Also update the Settings candidate cache if present:

```ts
qc.setQueryData(
  candidateQueryKeys.profile(id),
  (old: Candidate | undefined) =>
    old
      ? {
          ...old,
          resumeUrl: result.resumeUrl,
          resumeFileName: result.resumeFileName,
        }
      : old,
);
```

Then call the shared candidate invalidation helper.

The order should be:

```text
POST resume
     ↓
response contains resumeUrl + resumeFileName
     ↓
immediately update React Query caches
     ↓
UI instantly displays new resume
     ↓
invalidate/refetch candidate queries in background
```

This prevents the resume filename from disappearing while synchronization occurs.

# 10. CREATE A SHARED RESUME CACHE UPDATE HELPER

To avoid duplicating the same setQueryData logic, create something conceptually like:

```ts
export function setCandidateResumeCache(
  queryClient: QueryClient,
  candidateId: string | number,
  resume: {
    resumeUrl: string | null;
    resumeFileName: string | null;
  },
) {
  const id = String(candidateId);

  const updater = (old: any) =>
    old
      ? {
          ...old,
          resumeUrl: resume.resumeUrl,
          resumeFileName: resume.resumeFileName,
        }
      : old;

  queryClient.setQueryData(
    ["candidate-profile", id],
    updater,
  );

  queryClient.setQueryData(
    ["/api/candidates", id],
    updater,
  );

  queryClient.setQueryData(
    ["candidate", id],
    updater,
  );
}
```

Only include actual active query keys after repository inspection.
