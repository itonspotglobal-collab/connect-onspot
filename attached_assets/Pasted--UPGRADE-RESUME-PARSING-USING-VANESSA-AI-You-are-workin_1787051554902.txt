# UPGRADE RESUME PARSING USING VANESSA AI

You are working inside the existing **OnSpot / connect-onspot** project.

The resume auto-fill feature is now working end-to-end, but the extracted profile information is not accurate enough.

We need to improve resume interpretation by using **Vanessa AI's existing OpenAI functionality**.

Do NOT create an unrelated second AI integration.

Use the existing Vanessa/OpenAI infrastructure already present in the project.

---

# CURRENT PROBLEM

The deterministic resume parser is incorrectly interpreting resume content.

I have reproduced examples such as:

### Experience incorrectly parsed

Instead of a real experience entry, Talent Profile shows:

```text
frenzvallagahid81@gmail.com

backend development of an HR Management System
using C# and ASP.NET...
```

The email address is incorrectly being treated as a job/company/title.

Other random paragraph fragments are becoming separate Experience records.

---

### Professional Title incorrectly parsed

Profile Settings currently populated:

```text
Bachelor Of Science In Computer Engineering
```

as:

**Professional Title**

This is wrong.

That value belongs to Education.

Professional Title should instead be something such as:

```text
Software Developer
Full Stack Developer
Backend Developer
IT Specialist
```

depending on what the resume actually indicates.

---

### Professional Bio includes HTML markup

Current value contains:

```html
<p>To succeed and be a part of a competitive organization...</p>
```

The profile input must not display literal:

```text
<p>
</p>
```

Resume AI should return clean text.

# 4. USE STRUCTURED OUTPUT

Vanessa's resume analyzer must return machine-readable structured data.

Do NOT ask the AI to produce Markdown.

Do NOT parse free-form prose.

Use the project's currently installed OpenAI SDK capabilities for structured JSON/schema output where possible.

Define a Zod/schema contract.

Example concept:

```ts
const VanessaResumeSchema = z.object({
  personalInfo: z.object({
    fullName: z.string(),
    email: z.string(),
    phone: z.string(),
    location: z.string(),
    languages: z.array(z.string()),
  }),

  professional: z.object({
    title: z.string(),
    summary: z.string(),
    yearsOfExperience: z.string(),
    seniority: z.string(),
  }),

  skills: z.object({
    core: z.array(z.string()),
    secondary: z.array(z.string()),
  }),

  experience: z.array(
    z.object({
      jobTitle: z.string(),
      company: z.string(),
      startDate: z.string().optional(),
      endDate: z.string().optional(),
      duration: z.string().optional(),
      responsibilities: z.array(z.string()),
    })
  ),

  education: z.array(
    z.object({
      school: z.string(),
      degree: z.string(),
      fieldOfStudy: z.string().optional(),
      startYear: z.string().optional(),
      endYear: z.string().optional(),
    })
  ),

  certifications: z.array(
    z.object({
      name: z.string(),
      issuer: z.string().optional(),
      date: z.string().optional(),
    })
  ),

  confidence: z.object({
    overall: z.number(),
    title: z.number(),
    summary: z.number(),
    experience: z.number(),
    education: z.number(),
    skills: z.number(),
  }),
});
```

Adapt to the actual Candidate schema.

Do not create unnecessary database columns.

# 6. CRITICAL FIELD CLASSIFICATION RULES

Vanessa must understand the difference between:

```text
contact information
professional title
objective/summary
skills
experience
education
certifications
projects
languages
```

These categories MUST NOT contaminate one another.

---

# EMAIL RULE

An email address can NEVER become:

```text
jobTitle
company
degree
school
certification
skill
```

For example:

```text
frenzvallagahid81@gmail.com
```

must ONLY map to:

```ts
personalInfo.email
```

Never Experience.

---

# PHONE RULE

Phone numbers must only map to:

```ts
personalInfo.phone
```

Never experience/company/title.

---

# EDUCATION RULE

Values such as:

```text
Bachelor of Science in Computer Engineering
BS Computer Engineering
Bachelor of Arts
Master of Science
Diploma in Information Technology
```

are degrees/education.

They must NEVER automatically become:

```text
Professional Title
```

unless the resume explicitly identifies that phrase as the person's professional headline, which would be extremely unusual.

For the example:

```text
Bachelor Of Science In Computer Engineering
```

Vanessa should return:

```text
education.degree = Bachelor of Science in Computer Engineering
```

NOT:

```text
professional.title
```

---

# PROFESSIONAL TITLE RULE

Professional Title should represent the candidate's actual career role.

Determine it using this priority:

1. Explicit professional headline beneath the candidate's name
2. Explicit current professional title/profile heading
3. Most recent valid work-experience job title
4. Semantic inference from the person's actual professional experience and skills

Examples:

```text
Software Developer
Backend Developer
Full Stack Developer
Virtual Assistant
Customer Support Specialist
Accountant
IT Administrator
```

Do NOT use:

```text
degree
school
email
location
objective sentence
company
section heading
```

as the professional title.

If uncertain, return empty rather than inventing.

---

# 7. EXPERIENCE MUST BE SEMANTICALLY GROUPED

This is one of the most important improvements.

The current parser is fragmenting paragraphs into separate Experience entries.

Vanessa should understand that an Experience entry normally contains:

```text
Job Title
Company
Dates
Responsibilities / Achievements
```

Example:

```text
Software Developer
Alliance Software Inc.
2022 – 2024

- Developed HR management functionality using C# and ASP.NET.
- Built employee record and payroll modules.
- Developed React interfaces.
- Participated in code reviews and unit testing.
```

must become ONE entry:

```json
{
  "jobTitle": "Software Developer",
  "company": "Alliance Software Inc.",
  "duration": "2022 – 2024",
  "responsibilities": [
    "Developed HR management functionality using C# and ASP.NET.",
    "Built employee record and payroll modules.",
    "Developed React interfaces.",
    "Participated in code reviews and unit testing."
  ]
}
```

NOT four separate Experience records.


Recommended rule:

