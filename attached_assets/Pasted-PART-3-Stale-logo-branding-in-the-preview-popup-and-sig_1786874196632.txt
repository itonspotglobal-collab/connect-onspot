PART 4 — Most-common-searches suggestion chips

Change the suggestion chips under the search bar on /hire-talent to reflect
the MOST COMMON ACTUAL SEARCHES users have typed, not job-posting volume by
category (the current data source).

Design constraint, given the anonymous-search security decision already
made: do NOT log one row per individual search request, especially for the
unauthenticated /api/talent-search endpoint — that recreates the exact
DB-flooding risk that endpoint was specifically designed to avoid by not
writing a row per anonymous request. Instead:

1. Add a lightweight aggregation table (e.g. search_query_frequency:
   normalized_query text, count integer, last_searched_at timestamp) —
   normalize the query text (lowercase, trim, strip punctuation) before
   matching, so "Manage my inbox!" and "manage my inbox" count as the same
   entry. UPSERT with an incrementing count, not an INSERT per search.

2. This applies to BOTH /api/talent-search (anonymous) and
   /api/client/talent-search (authenticated) — every real search increments
   the matching normalized-query count, regardless of which endpoint.

3. Update GET /api/client/talent-search/suggestions (or create a variant
   used by /hire-talent specifically) to return the top 4-6 normalized
   queries by count, instead of top categories by job volume. Decide and
   confirm whether category-volume should stay as a fallback for when
   there's insufficient search history yet (e.g., fewer than some threshold
   of total searches logged) — don't show an empty or single chip if real
   search data is still thin.

4. Keep the existing static phrase-mapping approach as the fallback source
   if real query volume is too thin, but the primary source is now real
   user query text, lightly cleaned up for display (e.g., capitalize first
   letter) rather than a hand-written phrase per category.

Report back with real data: after some test searches, show the actual
aggregation table contents and confirm the chips reflect real frequency, not
a static list.
