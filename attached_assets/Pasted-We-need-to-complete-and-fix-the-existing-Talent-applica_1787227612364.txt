We need to complete and fix the existing **Talent application withdrawal flow** in the OnSpot / `connect-onspot` application.

## CURRENT BEHAVIOR

I tested the application workflow.

### Working

Talent can go to **My Applications** and click:

`Withdraw`

The Talent side correctly changes the displayed application status to:

`Withdrawn`

The existing frontend currently calls:

`PATCH /api/talent/applications/:applicationId/withdraw`

### Not working

2. The Client's **Job Submissions / Applications view does not reliably reflect `Withdrawn`** for that same application.

This must be fixed end-to-end.

### Talent side

* application status becomes `withdrawn`

* receive a persistent notification

* see the correct status after refresh and after logging out/back in

The Client notification should clearly communicate something like:

**Application withdrawn**

`{Talent Display Name} withdrew their application for {Job Title}.`

Use the application's existing notification design/style and data conventions.

Do not invent a second notification system.
