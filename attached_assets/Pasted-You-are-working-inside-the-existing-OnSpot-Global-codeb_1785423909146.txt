PHASE 3 — SERVER API

Implement or complete:

POST `/api/jobs/:jobId/apply`

This endpoint must be public because users apply before creating an account.

Accept JSON:

{
  "firstName": "Maria",
  "lastName": "Santos",
  "phone": "+63 912 345 6789",
  "email": "maria@example.com",
  "coverLetter": "Optional cover letter"
}

Server-side requirements:

1. Validate the job ID.
2. Return 404 if the job does not exist.
3. Reject applications when:
   - the job is not open;
   - the job is not approved for public display;
   - the job uses an external application method, unless the new requirement explicitly converts all public jobs to built-in applications.
4. Trim all values.
5. Normalize email to lowercase.
6. Validate email format.
7. Apply sensible length limits.
8. Validate the phone number without being overly restrictive.
9. Add rate limiting to prevent spam.
10. Use parameterized queries or Drizzle only.
11. Save the application in a transaction.
12. Never create a Talent account automatically before the applicant sets a password or completes the existing account-creation requirements.
13. Return a safe one-time continuation token, application ID plus signed token, or another secure server-issued handoff value.

Suggested success response:

{
  "success": true,
  "applicationId": "...",
  "continuationToken": "...",
  "nextUrl": "/talent/signup?application=..."
}

Do not put the applicant’s cover letter, phone, or full personal details in the URL.

Duplicate behavior:

- Return HTTP 409 with:
  `{ "error": "You have already applied for this job using this email." }`
- Do not create duplicate rows.

Add:

GET `/api/job-applications/continue/:token`

Purpose:
- Validate the short-lived continuation token.
- Return only the minimum prefill data needed by the Talent signup page:
  - firstName
  - lastName
  - email
  - phone
  - applicationId
  - job title

Add an authenticated linking operation, either inside the existing Talent registration endpoint or through:

POST `/api/job-applications/link`

Behavior:
- Require the newly authenticated Talent.
- Validate the continuation token.
- Ensure the registered email matches the application email, unless the project already has a verified email-change process.
- Set `talentId` to the newly created Talent user ID.
- Set `registrationStatus` to `linked`.
- Make this idempotent.
- Never allow one Talent to claim someone else’s application.

Use a short expiration for continuation tokens, such as 30–60 minutes. Store only a token hash if persistent storage is needed.
