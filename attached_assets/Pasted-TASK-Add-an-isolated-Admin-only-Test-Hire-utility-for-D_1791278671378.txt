TASK: Add an isolated Admin-only "Test Hire" utility for DEVELOPMENT/UAT
so I can test Contract Signing → Hired → Client Team → Timesheets and
related downstream features without changing the normal hiring workflow.

IMPORTANT:
The existing production hiring workflow is working and MUST NOT be
modified just to support testing.

Do NOT:
- change normal application status rules
- enable Hired in the normal status dropdown
- add an interview requirement
- remove formal pipeline guards
- weaken authorization
- create fake interview records
- automatically fake contract signatures
- make this available to ordinary Clients/Talents

============================================================
GOAL
============================================================

I have test Client/Admin/Talent accounts.

I need a controlled way to take a TEST Talent/application and bootstrap it
into the downstream hiring workflow so I can manually test:

- Offer
- Contract preparation
- PDF upload
- Contract sending
- Talent signing
- Client/Organization signing
- OnSpot signing
- Hired activation
- Client Team
- Timesheet
- clock sessions
- related downstream functionality

This must be isolated from the real hiring workflow.

============================================================
IMPLEMENTATION APPROACH
============================================================

Create a DEVELOPMENT/UAT-only Admin action such as:

[Test Hire]

or:

[Prepare Test Hire]

This action must NOT immediately set:

application.status = "hired"

Instead, it should create/prepare the minimum legitimate prerequisites
needed to enter the REAL downstream Offer/Contract workflow.

The purpose is to skip upstream recruitment steps during testing while
still testing Contract Signing and Hired activation for real.

============================================================
FEATURE FLAG
============================================================

Use an explicit server-side flag such as:

ENABLE_TEST_HIRING_TOOLS=true

Reuse the project's feature flag system if one already exists.

Default:

false

The server must be authoritative.

Do NOT implement this using:
- localStorage
- query parameters
- frontend-only checks
- hidden URLs
- browser flags

Prefer preventing it from operating in production entirely.

For example, use the project's existing environment/deployment detection
and fail closed in production.

If production environment detection is uncertain, report that rather than
assuming it is safe.

============================================================
TEST ACCOUNT RESTRICTION
============================================================

Do NOT allow this tool to operate on arbitrary real Talent accounts.

Audit whether the system already has a safe concept of:
- test users
- seed users
- development accounts
- sandbox accounts

Reuse that if available.

Otherwise implement the smallest safe test-account designation.

The server must verify that the selected Talent/account is explicitly
eligible for test hiring.

An Admin should NOT be able to accidentally click Test Hire on a real
production Talent.

============================================================
WHAT TEST HIRE SHOULD DO
============================================================

Audit the current schema/services first.

Determine the MINIMUM legitimate state required for the selected test
application/submission to enter the real downstream hiring pipeline.

Prefer using existing canonical services instead of direct database
updates.

The Test Hire preparation may, where required:

- ensure a valid application/submission exists
- associate it with the selected real test Client/job
- move it to an appropriate offer-eligible state such as Shortlisted
- establish formal-pipeline eligibility for this TEST submission
- create other minimum prerequisite records required by the existing
  downstream workflow

Do NOT create unnecessary duplicate submissions.

Do NOT fabricate an interview.

Do NOT mark an interview completed.

Do NOT create fake signatures.

Do NOT mark the contract executed.

Do NOT mark the Talent Hired.
