Update the Engagement Type / Duration behavior in the Create/Edit Job page.



1. Full Time behavior



If:



Engagement type = Full Time



then:



hide the Duration field completely

do not require duration

clear any previously selected duration value if the user switches from another engagement type to Full Time

make sure edit mode also respects this behavior



Example:



Full Time

→ no Duration field shown

2. Other engagement types



For engagement types where duration is relevant, keep the Duration dropdown visible.



Example:



Part Time

Contract

Project-Based

Temporary



Use the existing engagement-type values from the project. Do not invent new database values unless necessary.

The current options are too broad:

4. Keep data compatibility



Inspect how duration is currently stored.



If the database already stores strings, preserve the existing field and only update the allowed UI values.



If existing records contain old values such as:



1–3 months

3–6 months

6–12 months

Ongoing



do not break edit mode.



Handle legacy values safely.



For example, existing jobs with Ongoing may display as:



No fixed end date



while preserving compatibility with old records.



Do not perform a destructive migration unless required.



5. Create/Edit behavior



Example:



Engagement type: Part Time

Duration: 3 months



If the user changes:



Part Time → Full Time



immediately:



hide Duration

clear 3 months



If they change back:



Full Time → Part Time



show Duration again with no value selected.



6. Review step/public display



On the Review step and public job page:



do not show duration for Full Time jobs

show duration for applicable engagement types



Example:



Part Time · 3 months



or:



Project-Based · No fixed end date

7. Validation



Duration should remain optional unless the current business rules already make it required.



Do not create new validation rules without preserving existing behavior.
