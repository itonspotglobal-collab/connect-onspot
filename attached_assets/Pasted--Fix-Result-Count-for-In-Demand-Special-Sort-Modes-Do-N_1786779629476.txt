# Fix Result Count for `In Demand` / Special Sort Modes — Do Not Touch Working Filters

The main filters on `/find-work/jobs` are now working correctly.

Do NOT change or refactor the working:

* Category
* Location
* Contract Type
* Minimum Salary
* search filtering
* `/api/jobs/search` filter behavior

There is one remaining issue:

When selecting special Sort options such as:

* In Demand
* Urgently Hiring
* Top Remote
* Featured

the number shown as:

```text
5 roles found
```

does not update to match the actual number of cards visible.

Example from current test:

```text
5 roles returned by API

Select:
In Demand

Visible results:
3 jobs total

UI still says:
5 roles found
```

Expected:

```text
3 roles found
```

---

## Confirmed Root Cause

In:

`client/src/pages/FindWorkAllJobs.tsx`

the server response is:

```ts
const openJobs: Job[] = jobsData?.items ?? [];
const totalJobs = jobsData?.meta?.total ?? 0;
```

The main filters are already server-side.

This part is working and must remain unchanged.

Then the component calculates:

```ts
const filtered = useMemo(() => {
  const sorted = sortJobs(openJobs, sort);

  ...
  return [...featuredOnes, ...regularOnes];
}, [openJobs, sort]);
```

The issue is that:

```ts
sortJobs()
```

does more than sorting.

Some modes actually remove jobs.

For example:

```text
In Demand
Urgently Hiring
Top Remote
Featured
```

return only a subset of `openJobs`.

But the UI still displays:

```ts
totalJobs
```

from the API.

That is why the visible list and role count disagree.

---

# Important Scope Rule

Do NOT modify the working first filters.

Specifically, leave this existing request behavior intact:

```ts
if (category !== "All Categories")
  params.set("category", category);

if (contractType !== "All Types")
  params.set("contractType", contractType);

if (location !== "All Locations")
  params.set("location", location);

if (salary !== "Any pay")
  params.set("minSalary", ...);
```

Do NOT move these back to client-side filtering.

Do NOT change their query parameter names.

Do NOT change Category/Function matching again.

Only fix the count/special sort behavior.

# Required Fix

Create a separate count representing the final displayed result set.

For the current page:

```ts
const displayedJobsCount = filtered.length;
```

However, use it only for sort modes that actually filter the results.

Define:

```ts
const FILTERING_SORTS: SortOption[] = [
  "in-demand",
  "urgently-hiring",
  "top-remote",
  "featured",
];
```

Then derive:

```ts
const isFilteringSort = FILTERING_SORTS.includes(sort);

const displayedTotal =
  isFilteringSort
    ? filtered.length
    : totalJobs;
```

Use the actual project TypeScript style.
