# Replit Prompt — Update Client Create/Edit Job Posting to Use the New Simplified Full-Page Flow

We already redesigned the **Admin Create/Edit Job Posting** experience into a dedicated simplified full-page, multi-step flow.

The **Client** job posting experience has NOT been updated and is still using the older `JobFormModal.tsx` popup.

Your task is to update the Client Create/Edit Job Posting flow so it uses the **same simplified page-based UX architecture as Admin**, while preserving all client-specific API/auth/business logic.

Before changing anything, inspect the current code and report the exact client flow.

Primary files to inspect:

* `client/src/pages/ClientProfile.tsx`
* `client/src/components/JobFormModal.tsx`
* `client/src/pages/JobFormPage.tsx`
* `client/src/components/job-form/JobBasicsStep.tsx`

* `client/src/lib/jobFormUtils.ts`
* `client/src/App.tsx`
* client job API routes under `/api/client/jobs`
* admin job API routes under `/api/admin/jobs`

Confirm:

1. Which button currently opens the Client "Post a Job" flow.
2. Which handler opens `JobFormModal`.
3. How Client Edit currently opens `JobFormModal`.
4. Which API endpoints Client create/edit currently use.
5. How the authenticated client ID is determined server-side.

# API MODE REFACTOR

The existing `JobFormPage.tsx` is currently Admin-specific in places.

For example, it currently uses Admin API paths such as:

```text
GET /api/admin/jobs/:jobId
POST /api/admin/jobs
PATCH /api/admin/jobs/:jobId
```

Refactor this cleanly rather than sprinkling conditionals everywhere.

A reasonable approach:

```ts
const config = mode === "client"
  ? {
      listQueryKey: ["/api/client/jobs"],
      getJob: (id) => `/api/client/jobs/${id}`,
      createJob: "/api/client/jobs",
      updateJob: (id) => `/api/client/jobs/${id}`,
      returnPath: "/client-profile",
    }
  : {
      listQueryKey: ["/api/admin/jobs"],
      getJob: (id) => `/api/admin/jobs/${id}`,
      createJob: "/api/admin/jobs",
      updateJob: (id) => `/api/admin/jobs/${id}`,
      returnPath: "/admin/find-work",
    };
```

Use the actual current Client return path after auditing the app.

Do not blindly hardcode `/client-profile` if a better existing jobs/dashboard route is used.
