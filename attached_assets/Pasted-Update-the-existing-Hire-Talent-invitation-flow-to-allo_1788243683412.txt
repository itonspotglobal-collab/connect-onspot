6. IMPORTANT: CORRECT TIME CONVERSION
==================================================

This is critical.

The value from:

<input type="datetime-local">

has NO timezone information.

Do NOT blindly do:

new Date(inviteDateTime).toISOString()

after the user selects a timezone different from their browser timezone.

That would interpret the value in the browser's local timezone rather than the timezone the user selected.

Example:

User enters:

September 10, 2026
9:00 AM

and selects:

America/New_York

It must mean:

9:00 AM in America/New_York

even if the client's computer is physically in:

Asia/Manila

Convert that selected local wall-clock time to the correct UTC instant using the selected IANA timezone.

Then send:

{
  start: "<correct ISO UTC value>",
  timezone: "America/New_York"
}

Do NOT alter the user's selected wall-clock time.

Use an existing date/time library already present in the project if it has timezone support.

If the project already uses:
- date-fns-tz
- Luxon
- Temporal/polyfill

reuse it.

Do NOT add a new library unless necessary.
