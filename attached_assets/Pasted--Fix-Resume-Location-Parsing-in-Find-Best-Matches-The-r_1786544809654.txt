The remaining issue is specifically the `Location` field in Find Best Matches.

The uploaded resume DOES contain a location.

In the resume contact/header area, the content is:

```text id="x25wwe"

```

The parser successfully extracts:

```text id="2yij58"

```

## Important

Do NOT rename the application's canonical `location` field to `address` just to make this work.

The problem is parsing/mapping.

Resume terminology may be:

```text id="7f4x74"
Address
Current Address
Location
Current Location
Residence
Based in
```

or it may contain an UNLABELED location line in the contact block.

All of these should map into:

```ts id="c9fj2a"
candidate.location
```

or:

```ts id="fa0azx"
parsed.location
```

depending on the current architecture.

# 6. Avoid false positives

The same resume also contains:

```text id="056nox"
N. Bacalso Avenue, Cebu City
```

under Education.

That should NOT replace the candidate's personal location.

It is the university address, not necessarily the Talent's home/current location.

Therefore use this precedence:

```text id="nx4lnj"
explicit contact Address/Location
>
unlabeled contact-header geographic line
>
other location candidates
```

Do not scan the entire resume and simply return the first line containing `Cebu`.
