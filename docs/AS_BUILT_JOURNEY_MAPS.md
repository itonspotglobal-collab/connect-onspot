## Quick truth summary

This is a working source tree with real persisted job, applicant, organization, message, interview, offer, contract, time, invoice, notification, and admin workflows. It also contains visible dead routes, stale screens, mocked marketing/dashboard content, duplicate API registrations, conditional external transport, and API authorization gaps. “There is a page,” “there is a handler,” and “the workflow is live end-to-end” are not interchangeable conclusions.

## Status legend and reading this map

- **LIVE** — a complete code-wired user journey step is reachable from the stated UI, reaches a registered handler, and uses actual data or persistent business logic with the stated role/ownership boundary. It does **not** mean freshly runtime-tested or production-verified.
- **PARTIAL/STUBBED** — a page or handler exists, but a significant step is incomplete, mocked, miswired, configuration-dependent, semantically narrower than the UI suggests, or has a material access-control limitation.
- **LEGACY/DEAD** — the UI journey is not reachable through the actual outer route map, targets an unregistered/mismatched API, or is a stale redirect/alias. If a related backend handler exists, it is identified explicitly as **backend LIVE**; that does not make the user journey LIVE end-to-end.

Every major step below receives one of these exact labels. A conditional integration is described as a code capability with a configuration prerequisite, never as a provider that has been provisioned. UI protection is not treated as a substitute for backend authorization.

## Shared route, identity, data, and integration boundaries

### Outer routing takes precedence over nested router declarations

`AppContent` chooses public, client, or talent routers by its outer Wouter switch. A `<Route>` inside `ClientRouter` or `TalentRouter` is not reachable merely because its declaration exists: the outer switch must first mount that router for the URL. Admin pages are directly mounted in the public route switch and wrap their UI in `AdminProtectedRoute`. `client/src/App.tsx:209-322,370-473,554-670`.

- `ClientProtectedRoute` requires a main-authenticated `client`; `AdminProtectedRoute` requires main-authenticated `admin`. The frontend admin guard checks role, not admin subrole; API scopes are material. `client/src/components/ProtectedRoute.tsx:13-81,84-119`.
- The `dev_portal_role` comment describes a development bypass, but the guard still renders null when unauthenticated or role-mismatched. This is not evidence of usable access. `client/src/components/ProtectedRoute.tsx:22-30,70-80`.
- Client/talent contract-ending screens exist inside nested routers but are absent from the outer route table. Admin termination route is explicitly outer-mounted. `client/src/App.tsx:289-290,370-419,423-473,624-669`.
- `/inbox` is a compatibility redirect to `/messages`, not a separate inbox backend. `/talent-portal/applications` redirects to `/my-applications`. `client/src/pages/Inbox.tsx:1-14`; `client/src/App.tsx:596-598,644-645`.

### Identity models and ownership

- Standard account signup/login persists user identity; talent can additionally have a candidate row and a separate candidate JWT. Signup returns a regular JWT and candidate token when candidate creation succeeds. `server/routes.ts:3631-3640,3825-3903`.
- `authenticateJWT` adapts candidate tokens to user/talent identity; `authenticateTalentJWT` accepts only candidate JWTs. Generic `apiRequest` selects the main JWT before the candidate token, so mixed-session behavior matters. `server/routes.ts:491-699`; `client/src/lib/queryClient.ts:10-24`.
- Candidate-settings save explicitly requires talent-auth state. A talent with only the main JWT may open shared settings but receive “Not logged in” on that save. `client/src/pages/ProfileSettings.tsx:747-783`; candidate save: `client/src/hooks/useCandidateProfileSettings.ts:235-275`.
- Admin super-admin is represented by `admin_sub_role = NULL`; `talent_acquisition` and `client_success` are server-enforced scopes. The frontend admin wrapper checks only role. `server/routes.ts:773-825`; `client/src/components/ProtectedRoute.tsx:109-119`.

### Data is not all one store

The active exported app store is `DbStorage`, which extends `MemStorage`; selected methods use Postgres overrides and other methods can remain in memory. Schema declaration alone does not prove a current endpoint persists to that table. `server/storage.ts:2778-2791,4152`.

- Current durable paths include users, jobs, submissions/status history/email, organizations, messages, notifications, interviews, offers, hiring contracts, and modern invoice/timesheet tables. Example registration: `server/routes.ts:3542-3565`; billing logic: `server/routes/talentInvoices.ts:1029+`, `server/routes/timesheets.ts:85+`.
- Vanessa learning uses Replit Database (`server/services/db_manager.ts:1-3,892-924`); Vanessa conversation logs have Postgres-backed storage overrides (`server/storage.ts:2795-2825`). RAG index is a JSON file plus process cache (`server/services/ragService.ts:33-42,96-98,138-167`).
- Older `contracts`, `time_entries`, and `payments` coexist with modern `hiring_contracts`, `clock_sessions`, timesheet revisions, invoices, and payout records. Some client-team metrics still read old tables. `shared/schema.ts:305-308,1562-1715,1833-1854,1926-2081`; `server/routes.ts:15060-15104,15159-15257`.
- Historical migration reconciliation reports an inspection dated 2026-10-01 with expected trigger functions/triggers and migrations 0021–0031 missing **at that inspection**. This document does not recheck it and does not assert current deployed schema. `docs/migration-reconciliation.md:194-210`.

### Transport and providers are conditional

- Microsoft Graph email sends through client-credentials OAuth only when tenant/client/secret and an approved sender are configured; some interview-email paths intentionally skip when unconfigured. No delivery was tested. `server/services/microsoftGraphEmailService.ts:5-18,28-37,46-103,199-257,306-314`; `server/services/interviewEmailService.ts:153-169,278-285`.
- Graph calendar code queries interviewer availability (`getSchedule`) when credentials/calendar permissions are available. It does not create calendar events. `server/services/microsoftGraphCalendarService.ts:151-172,471-497`; availability routes: `server/routes.ts:9038-9156,9201-9228`.
- Object storage is Replit Object Storage via Google Cloud Storage SDK and requires path configuration. Candidate media handlers write real objects when configured; this does not imply upload success in a deployed environment. `server/objectStorage.ts:12-31,42-74`; `server/routes/candidateMedia.ts:113-149,187-224`.
- Stripe PaymentIntent code exists for inquiry/legal-ops flows, not hiring deposits/invoices/payouts. The LegalOps form is mismatched and does not mount Elements. PayPal is display text only; no PayPal SDK/handler was found. `server/routes.ts:13717-13752,13896-13979`; `client/src/pages/LegalOpsLanding.tsx:204-240,297-307`.
- Passport Google/LinkedIn login depends on provider credentials. Firebase helper is not the operative signup flow. LinkedIn profile import is a separate fabricated-sample endpoint. `server/replitAuth.ts:203-320`; `client/src/lib/firebase.ts:27-50`; `client/src/components/SignUpDialog.tsx:191-210`; `server/routes.ts:12563-12710`.

### Client journey details and exceptions

- **Invitations:** an authenticated client can issue an organization invitation; public token route renders preview. Accept requires login and authenticated `POST /api/organization-invitations/accept-by-token`; login preserves `returnTo`. Email delivery depends on configuration (`server/routes.ts:1304-1305,15920-16150`; `client/src/pages/PortalLogin.tsx:159-168`).
- **Search vs scaffold:** candidate search is real, and shortlist/favorite records persist. Search itself does not create a new job. A search-scaffold record is not a real approved job and cannot support normal invitation/application actions (`client/src/components/ClientTalentShortlistDialog.tsx:132`; `ClientTalentInviteDialog.tsx:253`; backend real search `server/routes.ts:17236-17272`).
- **External jobs:** anonymous public application is multipart and supports continuation before account creation; external-job navigation works only for an already configured external job record. Client job authoring forces `built_in_form` and null apply link; no external URL authoring control was found (`client/src/pages/JobApplyPage.tsx:241-243,634,770-810`; `server/routes.ts:16706-16731,18894-19030`; `shared/schema.ts:248`).
- **Messages:** generic direct messages are persisted and can start before invitation, including a thread whose `job_id` is null. This is separate from the formal pipeline's guarded messaging/name-reveal; an accepted invitation creates a pipeline-context thread. `server/routes.ts:11642-11871,18222-18235+`; `server/services/formalPipelineGuard.ts:4-18,30-36,40-54`.
- **Notifications:** bell uses persisted notifications and read state; Dashboard’s notices are static. `client/src/components/NotificationBell.tsx:361-429`; `server/routes.ts:12381-12532`; `client/src/pages/Dashboard.tsx:546-550`.
- **Billing:** tracked clock, approved timesheets, invoices, guarantee claims and payout schedules are different stages. A monthly client invoice is a database statement, not a payment transaction. See [billing handoff](#cross-role-handoff-invitation-to-hired-and-billing).
- **Dead navigation:** sidebar Contracts `/contracts` and Payments `/payments` have no client-router route. Projects, Performance, and ROI are placeholders. `/client/contract-endings` is linked but not outer-mounted (`client/src/components/ClientLayout.tsx:60-111`; `client/src/App.tsx:370-419,624-669`).

### Talent journey details and exceptions

- **Formal hiring is a fork, not the automatic next state for a public apply.** The public application path creates/links an application and status-history branch; this audit found no automatic conversion of `workflow_type='application'` into `client_invitation`. Formal interview/offer/contract endpoints use the guard described above; silent `client_shortlist` is also excluded. `server/services/formalPipelineGuard.ts:4-18,30-36,139-175,187-219`; public apply `server/routes.ts:18894-19030`.
- Formal pipeline status allowlist is exactly `new`, `under_review`, `reviewed`, `interviewing`, `offer_extended`, `offer_accepted`, `contract_sent`, `hired`; `invited` is before acceptance and `interview_scheduled` is not a canonical allowed status. `server/services/formalPipelineGuard.ts:40-54`.
- **Persisted “Find Best Matches” is not the TalentPortal match feed.** The outer `/find-best-matches` route hydrates candidate profile, requests open jobs, scores locally, persists candidate edits and culture evaluation. Scores use static weights/questions/canned narrative and a 2.8-second animation; profile-save failure is swallowed so the wizard can continue. `client/src/App.tsx:582-584`; `client/src/pages/FindBestMatches.tsx:1041-1325,2064-2084,2391-2529`; `server/routes.ts:8430-8507,8512-8607`.
- Resume extraction in that onboarding tries the Vanessa analyzer and falls back to a deterministic local parser; the analyzer is conditional on OpenAI configuration and may return 503. The local fallback is not proof of model analysis. `client/src/pages/FindBestMatches.tsx:2149-2218`; `server/routes.ts:12741-12779`; `server/services/vanessaResumeAnalyzer.ts:32-37,488-493`.
- **`/api/talent/matches` is a real persisted feed, but its panel is unreachable.** `TalentPortal` renders `TalentMatchedJobs`, but outer `/talent-portal` redirects home and `/get-hired` selects `PublicRouter`. `TalentPortal` also calls missing `/api/talent/my-applications`. Do not claim the old portal is live. `client/src/App.tsx:599,644-649`; `client/src/pages/TalentPortal.tsx:451-456`; `server/routes.ts:7367-7402`.
- **Culture-evaluation authorization:** `/candidate-profile/:candidateId` has a UI guard and candidate GET is public-sanitized, but culture GET/POST handlers lack auth middleware and POST accepts candidate id and updates culture score. This is a material API boundary; it is not an admin-verified assessment. `client/src/App.tsx:584-588`; `server/routes.ts:7832-7853,8435-8507`.
- **Public status badges:** public talent profile renders persisted `isVerified` and `isVetted`; public candidate sanitizer passes those flags while redacting contact/URLs. Ratings are not included in that projection, so a marketing rating display is not sourced from this API. `client/src/pages/TalentProfile.tsx:1295-1318`; `server/routes.ts:7637-7693`.
- **Job records vs old identifiers:** public detail/search handlers are DB-backed and return eligible approved/open job rows; an old/static identifier in a stale link is not a canonical persisted job record and need not resolve as one. External apply is a separate configured-record branch. `server/routes.ts:8512-8607`; `client/src/pages/FindWorkJob.tsx:682-715`.
- **Homepage proof content:** homepage talent cards query real candidate records, but Open Jobs falls back to `STATIC_JOBS` when fewer than three live results exist. Laptop mock metrics/people and testimonial blocks are fixed marketing content, not account data. `client/src/pages/Home.tsx:97-118,702-713,2175-2296,2300-2350`; `client/src/components/TestimonialCarousel.tsx:23-150`.
- **Legacy Get Hired:** profile/skills APIs exist, but its assessment/job-application start calls have no registered matching handlers and generic upload call does not match `/api/object-storage/*`. Its assessment result is static. `client/src/pages/GetHired.tsx:169-212,230-245,1032-1055`; `server/routes.ts:5394-5521`.
- **No learning/community/referral/reward flow:** no complete reachable real-data journey or assessment implementation was established in reviewed routes. A `skills_tests` or `assessments` schema declaration alone is not an implementation.
- **Active vs stale paths:** `/talent/payouts`, `/talent/clock`, `/talent/timesheets`, `/talent/invoices` are outer-mounted. `/talent/contract-endings`, `/hired-talent-portal/payouts`, and legacy portal components are not. `client/src/App.tsx:454-470,600-603,644-650`.

### Financial lifecycle distinctions

- **Legacy vs modern invoices:** `/client/billing` remains on older invoice-array/detail APIs; `/client/monthly-invoices` is a distinct newer monthly-statement UI. Modern `talent_invoices`, monthly statements and credit tables coexist with legacy `invoice_periods`/`invoices`. `client/src/pages/client/Billing.tsx:168-171,218-229`; `client/src/pages/Invoicing.tsx:112-125`; `shared/schema.ts:1926-2029,2049-2081,2149-2180`.
- **Formal lifecycle status:** only the accepted client-invitation workflow passes formal pipeline guards. Its status allowlist is exactly `new`, `under_review`, `reviewed`, `interviewing`, `offer_extended`, `offer_accepted`, `contract_sent`, and `hired`; `invited` and `interview_scheduled` are not canonical statuses in this allowlist. `server/services/formalPipelineGuard.ts:40-54`.
- **Clock vs old hours:** clock sessions and approved timesheet revisions are modern tracked-contract data; old `time_entries` remain read by some legacy client-team calculations. A modern hire appearing on team dashboard does not imply its hours are represented there. `shared/schema.ts:1833-1854`; `server/routes.ts:15159-15191`; `server/routes/timesheets.ts:97-150`.
- **Timesheet dispute/correction:** talent correction proposals, client disputes of approved periods, admin resolution and immutable revisions/audit are separate transitions. `server/routes/timesheets.ts:265-638`.
- **Missed clock-out:** source detects and persists a 16-hour condition when clock data is read. This is on-demand detection, not proof of a real-time monitoring alert. `server/routes.ts:3158-3247`.
- **Guaranteed claims and late credits:** claims are owned/client-authenticated and deadline/start gated; late claims apply to already-sent guaranteed invoices; admin approval creates a client credit memo, not a talent-side reversal. `server/routes/talentInvoices.ts:1140-1380`.
- **Payout schedule is not payout receipt:** automation can schedule payout when a held same-currency deposit covers obligations, but no provider transfer call was found. `server/routes/talentInvoices.ts:346-391`; manual legacy disbursement: `server/routes.ts:22637-22680`.
- **Contract ending:** backend logic can adjust/shorten/void drafts and reopen final tracked timesheet, but requester pages on client/talent are outer-route dead. Admin route is reachable. `server/routes/contractTerminations.ts:261-448`; `client/src/App.tsx:289-290,624-669`.
